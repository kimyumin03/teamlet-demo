flex와의 차이 — 한눈에

동일 기능을 어떻게 다르게 풀었는지

flex (현재)

  • 4 탭 보유 / 사용 / 월별 / 촉진 — 한 직원의 정보가 4곳에 흩어짐
  • 18 컬럼 가로 테이블 — 가로 스크롤 필수, 빈 셀이 70%+
  • 3 중 모달 부여 → 대상 검색 → 캘린더 stack
  • 7 가지 진행 상태 작성요청됨/관리자작성기간/승인진행중/반려/완료/작성기간지남/촉진취소
  • 상단 dropdown 2개 맞춤 휴가 부여 ▾ × 연차 조정 ▾
  • 0과 미적용 구분 없음 두 케이스 모두 빈 셀

Teamlet (이번)

  • 3 탭 현황(보유+월별) / 사용 내역 / 촉진 — 직원 중심 통합
  • 6 기본 컬럼 + side sheet 행 클릭 시 18종 휴가 전체 펼침
  • side sheet 1 단 부여·조정·정책 보기 모두 같은 패널에서
  • 4 가지 상태 대기 / 진행 / 완료 / 종료 (만료·취소 통합)
  • 액션 단일화 + 휴가 부여 한 버튼, 안에서 종류 선택
  • 0 vs 미적용 시각적 분리 0은 숫자, 미적용은 ─ + hatching

세부 설계 결정

디자인 시스템 토큰 및 인터랙션 패턴

1. 정보 위계

  • 최상단 KPI 4개 — 전사 평균 잔여 / 소진 임박 / 이번 달 사용 / 오늘 휴가 중. flex는 KPI 자체가 없음.
  • 탭 카운터를 row count가 아닌 actionable count로 변경 → 촉진 11(처리할 것)
  • 잔여 표시는 숫자 + bar + 색상 3중 인코딩 — 색약/다크모드 대응

2. 테이블 전략

  • 기본 6컬럼 고정: 이름 · 사번 · 연차 잔여/부여 · 사용 · 기타 휴가(요약 배지) · 소진 예정
  • "기타 휴가"는 부여된 종류만 배지로 노출 + +3으로 나머지 축약
  • 행 클릭 → 우측 360px side sheet에 18종 전체 펼침. 가로 스크롤 0.

3. 상태 / 색 시스템

  • 색만이 아닌 형태 + 색 2중 인코딩: 원형(완료) · 마름모(대기) · 사각(진행) · 반투명원(종료)
  • 색 팔레트 4가지로 제한: 회색(중립) · 황토(대기) · 잉크(진행) · 적색(반려/만료)
  • 잔여 임박은 warn 토큰 1개로 통일 — bar 색 = 텍스트 색

4. 부여 흐름

  • 모달 stack 제거 → 오른쪽 side sheet 1단으로 통합
  • 단계: ① 종류 선택 (radio) ② 시간 (일/시간/분) ③ 대상 (인라인 검색) ④ 사용 기간
  • 대상 검색은 같은 sheet 내 inline expand — 별도 모달 없음

5. 촉진 (큐 패턴)

  • 테이블이 아닌 4개 칸반 컬럼으로 — 관리자의 work queue
  • 상단에 "내가 처리할 N건" 명시 — 다른 모든 화면에서도 동일 패턴
  • flex의 7가지 진행상태를 의미 단위 4가지로 합침 (만료/취소 → 종료)

6. 빈 상태 / 미적용

  • "부여한 적 없는 종류"는 대시(─) + hatching으로 명시
  • "부여했지만 사용 0"은 숫자 0으로 — 두 상태 시각적 분리
  • side sheet 미적용 row는 dashed border + hatched bg — 정책 추가 진입점도 제공 가능
