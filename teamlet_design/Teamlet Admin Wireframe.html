관리자 영역 — 설계 원칙

권한별 노출 · 충돌 가능성 가시화 · 자동화의 자연어 표현

flex (현재)

  • 권한 그룹은 단순 ON/OFF 체크박스 — 범위/스코프 정보 없음
  • 권한 카테고리는 7개 가로 탭으로 분리 — 한 그룹 전체 권한을 한눈에 볼 수 없음
  • 문서함 설정은 체크리스트 모달로 추가 — 메타 정보(권한·보관·자동) 없음
  • 자동 발송은 별도 메뉴 깊숙이 — 어떤 이벤트에 무엇이 발송되는지 추적 어려움
  • 설정 메뉴 권한별 노출 처리는 있으나 운영 메뉴와 일반 설정 구분 모호

Teamlet

  • R / W / A × scope 매트릭스 — 권한의 실제 효과 가시화
  • 같은 7개 카테고리지만 카운터 + "권한 없음" 그룹화로 그룹별 권한 밀도 즉시 인지
  • 문서 유형 = 한 행 권한·수집 방식·보관·상태 인라인 편집
  • 자동 발송 = 자연어 IF→THEN 카드 · 트리거(노랑) · 액션(녹색) 색 분리
  • "운영" 그룹에 ADMIN 뱃지 권한별 노출 명시 (brief 준수)

세부 결정

권한 매트릭스 · 충돌 검사 · 보관 정책

1. 권한 매트릭스

  • 한 행 = 권한 × R / W / A × 범위
  • "부여 안 됨" 권한은 회색 + opacity로 시각적 격하 — 그룹 한계 명시
  • 상단 카테고리 탭에 부여된 권한 수 카운터 — 그룹별 권한 밀도 비교

2. 충돌 검사

  • 한 구성원이 여러 그룹에 속할 때 권한이 OR 합산됨
  • 상단 "충돌 검사" 버튼 → 같은 권한을 R/W 모두 부여하는 그룹 조합 찾아냄
  • 흔한 실수: 일반 구성원 + 커스텀 리뷰어 그룹의 권한 중복

3. 시스템 vs 커스텀

  • 시스템 그룹 3개(최고관리자 / 조직장 / 일반)는 이름·자동 부여 변경 불가
  • 커스텀 그룹은 자유롭게 생성 · 사용자가 수동 매핑
  • 두 영역 시각적 분리 (subhead "커스텀") — 시스템 망가뜨림 방지

4. 문서 유형 표

  • 한 행 = 아이콘 · 이름·설명 · 권한 · 수집방식 · 보관 · 상태
  • 수집 방식 3가지: 자동 발송 / 수동 업로드 / 요청 발급
  • flex의 "기본 문서 추가" 모달 → 표에서 직접 + 인라인 추가

5. 자동 발송

  • 한 카드 = 토글 + 자연어 IF · THEN 문장 + 메타
  • 색 인코딩: 트리거(노랑 bg) · 결과(녹색 bg) — 한눈에 흐름 파악
  • 각 카드에 마지막/다음 실행 · 로그 링크 — 운영 안전성 ↑

6. 보관 · 만료

  • 모든 문서 유형에 보관 기간 명시 (법정/사내 기준)
  • 만료 임박 문서는 페이지 상단 만료 임박 3건 카운터 노출
  • 만료 시 자동 알림 → 재발급/폐기 워크플로우 자동 생성
