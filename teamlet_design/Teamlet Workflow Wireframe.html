워크플로우 — 설계 원칙

brief의 3구분(요청/대기/완료) · 액션 우선 순서 · 결재선 가시화

일반 결재 시스템

  • 탭 순서가 시간순(요청 → 대기 → 완료) — 첫 화면에 액션 없음
  • 리스트에서 승인 불가 — 모든 결재는 상세 진입 필요
  • 결재선은 상세 페이지에 텍스트로만 존재
  • 결재 의사결정 정보(신청자 잔여, 근무 상황, 일정 충돌)가 흩어짐
  • 5+ 가지 문서 종류를 메뉴 트리로 분리 → 신규 문서 찾기 어려움

Teamlet

  • 탭 순서 = 우선순위 결재 대기를 1번 탭 + cta 카드로 노출
  • 리스트에서 인라인 승인/반려 — 단순 휴가는 1초 결재
  • 결재선이 리스트 + 상세 양쪽의 spine · 현재 단계 시각화
  • 신청자 컨텍스트 카드 우측 레일에 — 잔여·근무·충돌 즉시 확인
  • + 새 문서 작성 단일 CTA · 안에서 템플릿 검색

세부 결정

상태 · 색 · 결재선 · 인라인 액션

1. 상태 압축

  • 5가지: 작성중 / 진행중 / 승인 / 반려 / 회수
  • "승인진행중", "결재대기", "검토중" 등 동의어 표현 제거 → 진행중 1개로
  • "제출완료"는 상태 X, 이벤트 → 활동 이력에서만 노출

2. 결재선 시각화

  • 리스트: 미니 chip chain (신청 ✓ → 팀장 ● → HR ○)
  • 상세: 가로 stepper, 각 단계에 역할·이름·시점
  • 현재 단계는 잉크 fill + 굵게 — 색 + 두께 2중 인코딩

3. 문서 종류 색

  • 5개 종류만 색 chip: leave / expense / training / wfh / hr
  • 그 외는 회색 기본 chip — 색 인플레이션 방지
  • 같은 카테고리(예: 휴가)는 종류 무관 같은 색 — 시각 그룹화

4. 인라인 액션

  • 리스트 우측에 반려 / 승인 직접 노출 — 클릭 시 컨펌 (Cmd+Enter)
  • 단순 결재 (휴가, 재택)는 리스트에서 완결 가능
  • 금액·증빙·서명 필요한 결재는 상세로 이동 — 동선 차별화

5. 그룹화

  • 리스트는 마감 임박 / 이번 주 / 그 외로 시간순 그룹
  • 마감 임박 항목은 좌측 빨간 bar — 색 + 위치 2중 인코딩
  • 같은 그룹 내에서는 신청 시점 역순

6. 결재자 컨텍스트

  • 우측 레일에 신청자 미니 카드 · 결정에 필요한 5개 지표
  • "충돌 일정 없음" 자동 검증 → 빠른 승인 신호
  • 관련 이전 문서 자동 리스트 — 패턴 식별 (잦은 신청 등)
