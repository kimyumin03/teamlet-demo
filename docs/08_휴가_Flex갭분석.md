## 1. 우리가 이미 가진 것 (강점 — 헛삽질 방지)

데이터 모델은 이미 Flex 수준으로 설계되어 있다. **갭의 본질은 "모델은 있으나 UI/엔진이 못 따라간다"**이다.

- `LeaveType` — `grantMethod`(6종) / `grantUnit`(MINUTE·HOUR·DAY·UNLIMITED) / `paymentType`(PAID·UNPAID·PARTIAL_PAID) / `genderRestriction`(ALL·MALE·FEMALE) / `evidenceRequirement`(NONE·BEFORE·AFTER) / `isSystem`·`isRequired`
- `LeaveGrantMethod` enum: `ON_REQUEST · ON_OTHER_EXHAUSTED · MANUAL · ON_HIRE · PERIODIC · ON_TENURE`
  → Flex 부여방법(신청 시/연차 소진 시/관리자 직접/입사 시/반복/근속 시)과 **1:1 대응**
- `LeavePolicy` — `grantMode`(FISCAL_YEAR·HIRE_DATE) / `fiscalStartMonth` / `monthlyGrantRule` / `annualFirstYearRule` / `decimalRule`(ROUND_UP_DAY 등) / `expiryMonths` / `carryoverMaxDays` / `isDefault`
- `LeaveBalance` — 연도별 `grantedDays·usedDays·adjustedDays` + `expiryProcessedAt`(소멸/이월 멱등 마커)
- `LeaveTransaction` — 불변 원장(`GRANT·EXPIRE·USE·ADJUST`, 카테고리 `MONTHLY·ANNUAL·EXTRA_GRANT·ADJUSTMENT`)
- `LeaveRequest` — `formDocumentId`로 통합 결재(`FormDocument` LEAVE_REQUEST) 연결
- 연차 자동부여(MVP) — 정책 기반 멱등 부여 + 첫 해 월할 비례 (관리자 수동 실행)

## 2. A. 내 휴가 페이지 (`/leave`)

### 현재
- 탭: `overview`(개요) / `history`(이력) — 2탭 (`page.tsx` `VALID_TABS`)
- 개요: 연차 히어로 카드, 연간 사용 현황 바, 휴가 종류 그리드, 최근 신청 5건
- 이력: 상태 필터 + 신청 리스트 + 취소 버튼

### Flex (캡처 기준)
3탭 = **휴가 개요 / 연차 상세 / 연차 사용 계획**

#### 연차 상세 탭 (누락)
- 요약 카드 4개: `자동 부여(+N일)` / `소멸` / `사용` / `조정` (각 ⓘ 툴팁)
- 월별 원장 테이블 — 컬럼: `날짜 / 자동 부여 / 소멸 / 사용 / 조정 / 잔여`
  - 입사월 배지, 현재월 강조, 조정 컬럼 인라인 편집(연필)
  - 누적 잔여 표기 (예: 6월 +1 → 1일, 7월 +1 → 2일 …)
- 하단 안내: "소수점 넷째 자리에서 반올림하여 표기한 결과입니다."
- **판단**: 데이터(`LeaveTransaction`)는 이미 있음 → **집계 함수 + 표시 UI만 필요**. 가성비 최고 (우선순위 1).

#### 연차 사용 계획 탭 (누락 — 촉진 연계)
- 조회 기간(연도) 셀렉터
- 빈 상태: "연차 촉진 내역이 없어요. / 담당자가 연차 촉진을 시작하면 이 곳에서 연차 사용 계획을 작성할 수 있어요."
- **판단**: 촉진 엔진(섹션 6)에 종속 → 가장 늦게.

#### 사용한 기록 (개요 내)
- "반려 기록 포함" 토글, 연도 네비게이터(◀ 2026년 ▶) — 우리 개요에 없음.

## 3. B. 휴가 신청 모달

### 현재 (`components/leave/leave-request-button.tsx` + `lib/actions/leave.ts`)
- 필드: 휴가 종류 / 결재자(1명 드롭다운) / 시작일 / 종료일 / **사용 일수(숫자 직접 입력)** / 사유
- `requestLeaveAction` → `requestLeave` → `FormDocument`(LEAVE_REQUEST) 결재 생성

### Flex (캡처 D 플로우)
1. 휴가 카드 클릭 → 모달 헤더(휴가명 · 유급 여부)
2. 듀얼 캘린더로 **시작일 → 종료일** 선택 → "총 N일" **자동 계산**
3. "상세 일정 편집": 날짜별 **하루 종일 / 오전 반차 / 오후 반차 / 시간차**, 시작·종료 시간, **휴게시간 포함** 토글(반차 1시간 자동)
4. 등록 확인: 기간 요약 "1일 4시간", 사유 입력
5. **승인·참조 패널**: `참조` + `1단계 승인 / 2단계 …` (다단계 결재선)

### 갭
| 항목 | Flex | 우리 | 비고 |
|---|---|---|---|
| 일수 | 날짜 범위 → 자동(공휴일 제외) | **수기 입력** | 오타·악용 위험. `listCompanyHolidays` 있음 → 영업일 계산 가능 |
| 사용 단위 | 일/오전반차/오후반차/시간차 + 휴게 | 일 단위만 | 정책(사용 단위) 연동 필요 |
| 결재선 | 참조 + N단계 승인 | 결재자 1명 | `RecipientPicker` 재사용 원칙(Anti-Pattern #10) 적용 대상 |

**판단**: 매일 쓰는 핵심 → 우선순위 2. 1단계로 "일수 자동계산 + 반차"부터.

## 4. C. 연차 설정 (`/settings/leave-policies`)

### 현재
- 연차 자동부여 카드(수동 실행 버튼) + 정책 목록(`LeavePoliciesClient`)
- "소멸·이월 자동화는 아직 준비 중" 명시
- 모델은 풍부하나 UI는 부여 기준 위주

### Flex (캡처 E·F·C·B·E 모달들)

#### F. 연차 정책 편집 모달
- 승인·참조자 선택 / 승인 요청 시점(등록할 때·취소할 때 토글)
- 연차 사용 단위: `시간 | 반차 | 일` 세그먼트 (시간 선택 시 1·5·10·15·20·30분·1·2시간 중 — 30분 추천)
- **당겨쓰기 설정**: `자유롭게 사용 가능` / `사용량 제한(최대 N일)` — 미소진 시 다음 부여분에서 선차감
- 연차 부여 방식(→ B 모달) / 자동 소멸 설정(→ C 모달) / 스마트 연차 촉진(→ 섹션 6)

#### B. 연차 부여 방식 모달
- 탭 `회계일 | 입사일`, 부여 시작일 표기
- `회계일`(예: 1월 1일) / `입사자 월차`(매월 개근시 1일) / `입사자 1년 만근 연차`(첫 회계일에 근무한 기간의 연차) / `소수점 이하 연차`(일 단위 올림 등)
- 안내: 회계연도 기준은 취업규칙 명시 필요 + 퇴직 시 입사일 기준 재정산 필요
- **우리 매핑**: `grantMode·fiscalStartMonth·monthlyGrantRule·annualFirstYearRule·decimalRule` 거의 대응됨 → UI만.

#### C. 자동 소멸 설정 모달 (갭 큼)
- **미리보기 표**: `법정 소멸일` / `실제 소멸일` × `월차` / `연차`
- 월차 자동 소멸 시점: `소멸 안 함` / `입사일로부터 1년 후` / `입사일로부터 1년 후 첫 회계일`
- 연차 자동 소멸 시점: `소멸 안 함` / `부여일로부터 1년 후`
- **소멸 유예 기간**: 없음 / 19~24개월 (월차·연차 각각)
- **우리 매핑**: `expiryMonths` 단일 필드뿐. **월차/연차 분리 + 유예기간 + 실제/법정 소멸일 개념 없음** → 모델 확장 필요.

#### E-1. 퇴직자 연차 조정 기준 설정 모달 (없음)
- 라디오: `구성원에게 유리한 기준`(기본, 법정 vs 회사부여 중 큰 값) / `항상 근로기준법 기준`
- **우리**: 모델·UI 없음.

### 갭 요약 (C)
- 모델 확장 필요: 당겨쓰기 한도, 월차/연차 소멸 분리 + 유예기간, 퇴직자 조정 기준, 사용 단위(시간 granularity)
- 스마트 연차 촉진 = 섹션 6 (특대)

## 5. D. 맞춤 휴가 설정 (`/settings/leave-types`)

### 현재 (`leave-types-client.tsx`)
- 노출 필드: 부여 방식 / 급여 유형 / 부여 단위 / 기본 부여량 / (체크박스)
- **모델엔 있으나 폼에 없음**: `genderRestriction`, `evidenceRequirement`
- 목록 표: 부여 방식·급여 배지

### Flex (캡처 G + 맞춤휴가 추가 모달 전체)

#### 기본 폼
| 필드 | 옵션/동작 |
|---|---|
| 부여 방법 | (조건) 신청 시 / 연차 소진 시 / 관리자 직접 / 입사 시 · (주기) 반복 부여 / 근속 시 부여 |
| 부여 단위 | 분 / 시간 / 일 / **신청하는 만큼** |
| 부여 시간 | 숫자 + 단위(부여 단위 연동) |
| 사용 단위 | **한번에 모두 사용** ↔ **나눠서 사용**(일·반차·시간차 N분: 제한없음/5·10·15·20·30분·1·2시간) |
| 급여 지급 유무 | 유급 / 무급 / **일부 유급(%)** |
| 승인·참조 사용 | 결재선 모달 |

#### 부여 방법별 동적 폼 (중요)
- `관리자 직접 부여`: 부여 단위·부여 시간 **숨김**
- `반복 부여`: **반복 주기** 필드 추가 (매년/매월, 그룹 입사일 기준 토글, "N년차/N개월차부터")
- `근속 시 부여`: **부여 시점** 필드 추가 (N년 근속 시)

#### 추가 설정 (접이식, 전부 누락)
| 필드 | 옵션 |
|---|---|
| 사용 가능 성별 | 모두 / 남성 / 여성 (모델 O, UI X) |
| 증명 자료 제출 | 없음 / 사전 제출 / 사후 제출 (모델 O, UI X) |
| 제외 대상 설정 | 근로유형·조직 선택 (모델·UI X) |
| 휴일에 등록된 휴가 차감 | 토글 (모델·UI X) |

#### 필수(법정) 휴가 시드 (Flex 19종 참고)
가족돌봄 · 군소집훈련 · 난임 치료 · 배우자출산 · 보건 · 보상 · 산전후(본인/미숙아/다태아) · 유산·사산(+다태아) … + 회사 재량(결혼-본인/자녀 · 리프레시 · 병가 · 비상 · 조의 2종 · 포상)

### 갭 요약 (D)
- 동적 폼 분기(반복 주기·부여 시점), 사용 단위, 일부 유급 %(저장 필드 없음)
- 추가 설정 4종(성별·증명은 모델만, 제외/휴일차감은 신규)
- 휴가 종류별 승인·참조선

## 6. E. 월차·연차 촉진 (특대 — 법정 절차)

> 근거: 근로기준법 제61조 / 웨비나 PDF p4~12, 16 / 스마트 촉진 설정 캡처

### 6.1 제도 의의
회사가 **법 절차대로 적법하게** 사용을 촉구했음에도 근로자가 미사용 시 → **미사용 연차수당 지급 의무 면제**. 미실시 시 수당 지급. (회사의 강한 동기)

### 6.2 연차 촉진 (1년 이상 재직자) — 회계일 기준 예시 (부여 1.1 / 소멸 12.31)
```
 7.1 ─ 7.10        7.11 ─ 7.20         7.20 ─ 10.31           ~ 12.31
 [1차 촉진]         [근로자 응답]        [2차 촉진]              [잔여 사용]
 회사: 미사용일수   근로자: 10일 내      회사: 미제출자에게      제출자는
 안내 + 사용시기    사용시기 지정 통보   사용시기 지정·서면통보   잔여 사용
 지정 서면 촉구
 (소멸 6개월 전)                        (소멸 2개월 전까지)
```
- 1차: 소멸 6개월 전 기준 10일 이내
- 근로자: 촉구받은 때부터 10일 이내 사용시기 지정·통보
- 2차: 미제출자 대상, 소멸 2개월 전까지 회사가 시기 지정·서면 통보

### 6.3 월차 촉진 (1년 미만 재직자) — 총 11일, **2그룹 분리**
> 2020 개정: 1년 미만 월차는 발생일 무관 **입사일로부터 1년이면 전부 소멸**

| 차수 | 대상 월차 | 시점 | 응답 |
|---|---|---|---|
| 1차 | **1~9번째** 월차 잔여 | 소멸 3개월 전 (1년 끝나기 3개월 전, 예 10.1~10.10) | 10일 이내 제출 |
| 2차 | **10~11번째** 월차 잔여 | 소멸 1개월 전 | 10일 이내 제출 |

- ⚠️ **FAQ Q21 핵심**: 2차 촉진 수량 = 10·11번째 월차분만. 잔여 7개여도 촉진 수량은 2개.
- 서면 촉구 후 발생분은 1년 끝나기 5일/10일 전 등 별도 일정(PDF p9~12 참조).

### 6.4 회계일 vs 입사일 기준
- 회계일: 전원 동일 일정 → 일괄 관리.
- 입사일: 사람마다 소멸일 상이 → 수동 관리 사실상 불가 → **스마트 자동 촉진의 존재 이유**.

### 6.5 법적 효력 (전자문서)
서면 원칙이나, **전자결재체계 완비** + 기안·결재·시행이 개인별로 명확히 촉구/통보되면 전자문서 인정 (근로개선정책과-5353, 2011.12.19).
→ 우리의 `FormDocument` 결재 인프라가 법적 근거 충족 가능.

### 6.6 스마트 촉진 설정 (Flex 캡처 F)
