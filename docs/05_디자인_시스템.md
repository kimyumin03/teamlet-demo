## 0. 디자인 철학

### Visual DNA
- **Flat · 정확함 · 신뢰감** — HR은 "기록과 결재"의 도메인. 가벼움보다 명확함.
- **Whitespace 우선** — 정보 밀도보다 가독성. 한국 사용자에게 익숙한 깔끔한 레이아웃.
- **Subtle Color** — 컬러는 의미를 전달할 때만. 장식 X.
- **Predictable** — 같은 액션은 항상 같은 위치·같은 색. 학습 비용 최소화.

### Anti-Flex 가이드 (절대 어기지 말 것)
1. **그라데이션 금지** — `from-* to-*` Tailwind 클래스 사용 X
2. **비비드 그린 단독 사용 금지** — `#22c55e` 류
3. **둥근 정사각형 큰 아이콘 컨테이너 금지** — Flex 시각적 시그니처
4. **CTA 버튼은 슬레이트 또는 액센트 블루** — 절대 초록 X
5. **이모지 시그니처 금지** — 액션 카드의 큰 컬러풀 이모지 (✅💜✏️ 등 그대로 카피 금지). Lucide 또는 Tabler 아이콘 사용

## 1. 컬러 토큰 (Cool Slate)

### 1-1. Primary Ramp — Slate

Tailwind v4의 `@theme` 토큰으로 정의:

```css
@theme {
  /* Primary: Slate (브랜드 메인) */
  --color-slate-50:  #F8FAFC;
  --color-slate-100: #F1F5F9;
  --color-slate-200: #E2E8F0;
  --color-slate-300: #CBD5E1;
  --color-slate-400: #94A3B8;
  --color-slate-500: #64748B;
  --color-slate-600: #475569;
  --color-slate-700: #334155;
  --color-slate-800: #1E293B;
  --color-slate-900: #0F172A;
  --color-slate-950: #020617;
}
```

**용도**:
- 50~100: 배경 (페이지 / 카드 보조 / 비활성)
- 200~300: 보더, 디바이더, hover 배경
- 400~500: 보조 텍스트, 아이콘
- 600~700: 본문 텍스트, 보더 강조
- 800~900: 제목, **Primary 버튼 배경**, 강한 텍스트

### 1-2. Accent Ramp — Cool Blue

```css
@theme {
  /* Accent: Cool Blue (포커스, 링크, 정보) */
  --color-blue-50:  #EFF6FF;
  --color-blue-100: #DBEAFE;
  --color-blue-200: #BFDBFE;
  --color-blue-400: #60A5FA;
  --color-blue-500: #3B82F6;
  --color-blue-600: #2563EB;
  --color-blue-700: #1D4ED8;
  --color-blue-800: #1E40AF;
  --color-blue-900: #1E3A8A;
}
```

**용도**:
- 링크, 포커스 링, 진행 중 상태
- 보조 CTA (Slate 800이 메인 CTA, Blue 600이 보조)

### 1-3. Semantic Colors (절대 변경 금지 — 표준 의미)

```css
@theme {
  /* Success — 승인, 완료, 양호 */
  --color-success-50:  #F0FDF4;
  --color-success-100: #DCFCE7;
  --color-success-500: #22C55E;  /* ⚠️ 절대 메인 컬러 아님, 의미적 success만 */
  --color-success-700: #15803D;
  --color-success-800: #166534;

  /* Warning — 적용일 칩, 주의 */
  --color-warning-50:  #FFFBEB;
  --color-warning-100: #FEF3C7;
  --color-warning-500: #F59E0B;
  --color-warning-700: #B45309;
  --color-warning-800: #92400E;

  /* Destructive — 반려, 삭제, 위험 액션 (Dirty Guard "나가기") */
  --color-destructive-50:  #FEF2F2;
  --color-destructive-100: #FEE2E2;
  --color-destructive-500: #EF4444;
  --color-destructive-600: #DC2626;
  --color-destructive-700: #B91C1C;

  /* Info — 일반 알림, 강조 박스 */
  --color-info-50:  #EFF6FF;
  --color-info-100: #DBEAFE;
  --color-info-500: #3B82F6;
  --color-info-700: #1D4ED8;
}
```

⚠️ **`success-500`은 Flex의 메인 그린(#22C55E)과 우연히 같음**. 하지만 의미적 success 용도로만 사용 (예: "승인 완료" 체크 아이콘). **메인 CTA 버튼이나 브랜드 컬러로 절대 사용 금지**.

### 1-4. Semantic Tokens (코드에서 실제로 쓰는 이름)

```css
@theme {
  /* Backgrounds */
  --color-background:           var(--color-slate-50);    /* 페이지 배경 */
  --color-background-primary:   #FFFFFF;                   /* 카드, 모달 */
  --color-background-secondary: var(--color-slate-100);   /* 보조 패널 */
  --color-background-muted:     var(--color-slate-50);    /* 비활성 인풋 */

  /* Foregrounds (텍스트) */
  --color-foreground:           var(--color-slate-900);   /* 본문 기본 */
  --color-foreground-muted:     var(--color-slate-600);   /* 보조 */
  --color-foreground-subtle:    var(--color-slate-400);   /* 힌트 */
  --color-foreground-inverse:   #FFFFFF;                  /* 어두운 배경 위 */

  /* Borders */
  --color-border:               var(--color-slate-200);
  --color-border-strong:        var(--color-slate-300);
  --color-border-focus:         var(--color-blue-500);

  /* Brand / CTA */
  --color-primary:              var(--color-slate-900);   /* 메인 CTA 배경 */
  --color-primary-foreground:   #FFFFFF;
  --color-primary-hover:        var(--color-slate-800);

  --color-accent:               var(--color-blue-600);    /* 보조 CTA, 링크 */
  --color-accent-foreground:    #FFFFFF;
  --color-accent-hover:         var(--color-blue-700);

  /* Sensitive (자물쇠 아이콘이 붙는 영역) */
  --color-sensitive-bg:         var(--color-slate-100);
  --color-sensitive-border:     var(--color-slate-300);
}
```

## 2. 타이포그래피

### 2-1. 폰트 패밀리

```css
@theme {
  --font-sans: "Pretendard Variable", "Pretendard", -apple-system,
               BlinkMacSystemFont, system-ui, sans-serif;
  --font-mono: "JetBrains Mono", "D2Coding", ui-monospace, monospace;
}
```

**Pretendard 선택 이유**:
- 한국어 + 영문 + 숫자 모두 최적화된 가변 폰트
- 한국 SaaS 표준 (토스, 라인 등 사용)
- Flex 폰트와 다른 무게감 (Flex는 다른 한글 폰트 — 변별성 확보)

### 2-2. 타입 스케일

| 토큰 | 크기 | 라인 높이 | 무게 | 용도 |
|---|---|---|---|---|
| `text-xs` | 12px | 16px | 400 | 캡션, 칩 라벨 |
| `text-sm` | 13px | 18px | 400 | 보조 텍스트, 폼 라벨 |
| `text-base` | 14px | 22px | 400 | **본문 기본** |
| `text-md` | 15px | 24px | 400 | 강조 본문 |
| `text-lg` | 17px | 26px | 500 | 카드 제목, 모달 부제 |
| `text-xl` | 20px | 28px | 600 | 섹션 제목 |
| `text-2xl` | 24px | 32px | 600 | 페이지 제목 |
| `text-3xl` | 30px | 38px | 700 | 대시보드 메인 |

### 2-3. 무게

| 무게 | 용도 |
|---|---|
| 400 (Regular) | 본문 전부 |
| 500 (Medium) | 라벨, 카드 제목, 강조 |
| 600 (SemiBold) | 페이지 제목 |
| 700 (Bold) | 거의 안 씀 (대시보드 메인 카운터만) |

⚠️ **얇은 무게 사용 금지** — 300 이하는 한글에서 가독성 떨어짐

## 3. 간격 / 모서리 / 그림자 토큰

### 3-1. Spacing (Tailwind 표준 따라감, 4px 그리드)

```
1   = 4px
2   = 8px
3   = 12px
4   = 16px   ← 기본 패딩 / 컴포넌트 내부 간격
6   = 24px   ← 카드 패딩 / 모달 내부
8   = 32px   ← 섹션 간 간격
12  = 48px   ← 큰 섹션 분리
16  = 64px   ← 페이지 상하 여백
```

### 3-2. Border Radius

```css
@theme {
  --radius-sm:  4px;   /* 칩, 작은 배지 */
  --radius-md:  6px;   /* 인풋, 작은 버튼 */
  --radius-lg:  8px;   /* 카드, 큰 버튼 */
  --radius-xl:  12px;  /* 모달, 큰 카드 */
  --radius-2xl: 16px;  /* 대형 컨테이너 (회사 페이지 헤더 등) */
  --radius-full: 9999px;  /* 칩, 아바타 */
}
```

⚠️ **둥근 정사각형 (큰 아이콘 컨테이너) 금지** — Flex의 시각적 시그니처. 우리는 평범한 원형 아바타 + 라벨 사용.

### 3-3. Shadow (절제된 그림자만)

```css
@theme {
  --shadow-xs:    0 1px 2px rgba(15, 23, 42, 0.04);
  --shadow-sm:    0 1px 3px rgba(15, 23, 42, 0.06), 0 1px 2px rgba(15, 23, 42, 0.04);
  --shadow-md:    0 4px 8px rgba(15, 23, 42, 0.08);
  --shadow-lg:    0 10px 24px rgba(15, 23, 42, 0.10);
  --shadow-focus: 0 0 0 3px rgba(59, 130, 246, 0.4);  /* 포커스 링 */
}
```

**사용 원칙**:
- 카드: 기본 그림자 없음, `border` 만 사용
- 드롭다운/팝오버: `shadow-md`
- 모달: `shadow-lg` + 백드롭
- ⚠️ 큰 글로우, 멀티 레이어 그림자 금지

## 4. 핵심 컴포넌트 명세 (HR 도메인 패턴)

이 컴포넌트들이 우리 차별화의 핵심. shadcn/ui 베이스 위에 **HR 도메인 전용 컴포넌트**를 얹어서 만들어. 모두 `packages/ui/patterns/`에 위치.

### 4-1. AppliedDateChip (적용일 칩) ⭐

**역할**: 모든 인사 변경 모달의 우측 상단에 표시. "이 변경이 언제부터 적용되는지" 명시.

**Props**:
```tsx
type AppliedDateChipProps = {
  value: Date;
  onChange: (date: Date) => void;
  presets?: { label: string; date: Date }[];  // 기본: 오늘 / 내일 / 다음 달 1일
  warning?: 'retroactive' | 'future' | null;  // 과거/미래일 시 경고
}
```

**시각**:
- 기본 상태: `bg-warning-50 text-warning-800 border-warning-200` 칩, 라벨 "적용일 오늘"
- 클릭 시: 캘린더 팝오버 + 빠른 선택 (오늘/내일/다음 달 1일)
- 과거일 선택 시: 우측에 ⚠️ 아이콘 + tooltip "소급 적용되어 과거 데이터에 영향"
- 미래일 선택 시: 우측에 🕐 아이콘 + tooltip "예약 변경"

**Flex와 다른 점**: Flex는 주황색 단색 칩 + "적용일 오늘" 텍스트만. 우리는 **과거/미래 시각 표시 + 영향 범위 미리보기** 추가.

```tsx
<AppliedDateChip
  value={today}
  onChange={setDate}
  warning={isRetroactive ? 'retroactive' : null}
/>
```

### 4-2. RecipientPicker (받는 사람 선택) ⭐⭐ 4곳 재사용

**역할**: 결재선 승인자/참조자/정보변경 결재/동료에게 전달 — 4개 시나리오에서 동일 컴포넌트.

**Props**:
```tsx
type RecipientPickerProps = {
  mode: 'single' | 'multi';
  value: RecipientSelection;
  onChange: (selection: RecipientSelection) => void;

  // 옵션
  showAllEmployees?: boolean;     // "전체 구성원" 옵션 노출
  showOrganizations?: boolean;    // 조직 단위 선택 가능
  showSubOrgsToggle?: boolean;    // "하위 조직 함께 선택" 체크박스
  scopeFilter?: Permission;       // 권한 scope 적용 (조회 가능한 사람만)

  placeholder?: string;
}

type RecipientSelection = {
  type: 'all' | 'organizations' | 'employees';
  organizationIds?: string[];
  includeSubOrgs?: boolean;
  employeeIds?: string[];
}
```

**시각** (Flex 패턴 기반 + 우리 변주):
- 좌측: 후보 패널 (검색바 + "조직도 보기" 토글 + 리스트)
- 우측: 선택됨 패널 (다중 선택 시 칩 그룹, 빈 상태 "선택없음")
- 하단: 체크박스 "하위 조직 함께 선택"

**Flex와 다른 점**:
- 검색 결과에 **권한 scope 시각화** — 내가 볼 수 없는 사람은 회색 + 자물쇠 아이콘
- 최근 선택한 사람 **5명 빠른 선택 칩** (상단)
- 검색 시 **한국어 형태소 매칭** ("김유" → "김유민" 매칭)

### 4-3. JumpChips (점프 칩) ⭐

**역할**: 긴 폼(구성원 상세 등)의 우측 사이드에 섹션 네비게이션.

**Props**:
```tsx
type JumpChipsProps = {
  sections: { id: string; label: string; icon?: ReactNode }[];
  activeId?: string;  // 스크롤 위치 기반 자동 활성화
}
```

**시각**:
- 작은 라운드 칩 그리드 (2-column)
- 활성 칩: `bg-slate-900 text-white`
- 비활성: `bg-slate-100 text-slate-600`
- 클릭 시: 해당 섹션으로 부드러운 스크롤 + 잠깐 하이라이트

**Flex와 다른 점**: Flex는 단순 칩 리스트. 우리는 **현재 위치 자동 추적 + 부드러운 스크롤** 추가.

### 4-4. DirtyGuardModal (미저장 가드) ⭐

**역할**: 폼 수정 중 페이지 이탈 시도 시 차단.

**Props**:
```tsx
type DirtyGuardModalProps = {
  isDirty: boolean;  // react-hook-form formState.isDirty
  title?: string;    // 기본: "저장되지 않은 변경 사항이 있어요"
  description?: string;
  primaryLabel?: string;   // 기본: "나가기"
  secondaryLabel?: string; // 기본: "이어서 진행하기"
}
```

**시각**:
- 모달 (`shadow-lg` + 백드롭)
- Primary 버튼 = **"나가기"** with `bg-destructive` (위험 액션이라 빨강)
- Secondary 버튼 = **"이어서 진행하기"** with `bg-transparent text-foreground border`
- 좌측 상단 ⚠️ 아이콘 (`text-warning-500`)

**Flex 검증 패턴**: Flex는 Primary가 코랄/주황 ("나가기"가 destructive). 우리는 동일하지만 **`destructive-600` 빨강**으로 더 명확하게.

### 4-5. RetroactiveWarning (소급 영향 경고) ⭐

**역할**: 정책 변경 시 과거 데이터에 재계산 영향이 있음을 미리 명시.

**Props**:
```tsx
type RetroactiveWarningProps = {
  title: string;            // 기본: "이 변경은 과거 데이터에도 영향을 줘요"
  affectedScope: string;    // "입사일 이후 연차 자동 부여 내역"
  estimatedImpact?: string; // "12명의 직원, 약 47건"
  onPreview?: () => void;   // "영향 미리보기" 클릭 핸들러
}
```

**시각**:
- 옅은 `bg-warning-50 border-warning-200` 인포 카드
- 좌측 ⚠️ `text-warning-700` 아이콘
- 본문 + 영향 범위 + "영향 미리보기" 링크 버튼

**Flex와 다른 점**:
- Flex는 단순 텍스트 경고
- 우리는 **영향 범위 추정 + 미리보기 모달** — 차별화 핵심
- "12명의 직원, 약 47건의 휴가 트랜잭션이 재계산됩니다" 같은 정보

### 4-6. EmptyState (빈 상태) ⭐

**역할**: 모든 빈 리스트/페이지의 표준 컴포넌트.

**Props**:
```tsx
type EmptyStateProps = {
  icon?: ReactNode;       // Lucide 아이콘
  title: string;
  description?: string;
  action?: {
    label: string;
    onClick: () => void;
    variant?: 'primary' | 'secondary';
  };
}
```

**시각**:
- 중앙 정렬, 세로 배치
- 회색조 아이콘 (`text-slate-300`, 큰 사이즈 48px)
- 제목 (`text-lg text-foreground`)
- 설명 (`text-sm text-foreground-muted`, 한 줄)
- 액션 버튼 (선택)

**전 영역 일관 사용**: 알림 / 휴가 리스트 / 결재 문서 / 검색 결과 / 구성원 / 인사노트 등

### 4-7. ApprovalLineDrawer (결재선 진입점) ⭐

**역할**: 모든 변경 모달의 우측 상단 ⚙ 아이콘 클릭 시 열리는 결재선 설정 패널.

**Props**:
```tsx
type ApprovalLineDrawerProps = {
  approvalPolicyId: string;          // 시스템 기본 정책
  value: ApprovalLine | null;        // 사용자 변경 가능 시
  onChange?: (line: ApprovalLine) => void;
  allowModification?: boolean;       // 정책에서 "변경 허용" 칩 ON 시
}
```

**시각**:
- 우측 사이드 드로어 (Sheet 패턴)
- 상단: 정책 이름 + "기본 결재선" 라벨
- 참조자 섹션 (수정 가능 시 RecipientPicker)
- N단계 결재 섹션 (각 단계 = 1명 또는 조건식)
- 변경 허용 OFF일 때: 읽기 전용 시각 + "이 양식은 결재선 변경이 불가능해요" 안내

**Flex 패턴 그대로 + 우리 변주**:
- Flex는 상단에 톱니바퀴(⚙) 단독 — 가독성 떨어짐
- 우리는 ⚙ + "결재선" 텍스트 → 명확함
- 결재선이 비어있을 때 빨간 배지(`!`)로 명시

### 4-8. BidirectionalView (양방향 뷰) ⭐

**역할**: 권한 그룹 ↔ 구성원 권한 같은 양방향 데이터를 두 뷰로 토글.

**Props**:
```tsx
type BidirectionalViewProps<TLeft, TRight> = {
  leftView: { id: string; label: string; render: () => ReactNode };
  rightView: { id: string; label: string; render: () => ReactNode };
  activeViewId: string;
  onChange: (viewId: string) => void;
  helpText?: string;  // "양방향으로 조회 가능해요. 디버깅에 도움돼요."
}
```

**시각**:
- 상단 탭 토글 (Tabs 컴포넌트)
- 우측에 도움말 툴팁 (?) 아이콘
- 활성 뷰 콘텐츠 영역

**적용 예**:
- 설정 > 권한: "권한 그룹별" / "구성원별"
- 휴가: "휴가 종류별" / "구성원별 잔여"
- 결재: "내가 결재할 것" / "내가 신청한 것"

### 4-9. SensitiveLock (민감 정보 자물쇠) ⭐

**역할**: 권한 없는 사람에게 일부 정보 숨김. 자물쇠 아이콘 + 이유 명시.

**Props**:
```tsx
type SensitiveLockProps = {
  reason: string;  // "본인 또는 인사 권한자만 볼 수 있어요"
  fallback?: ReactNode;  // 마스킹된 표시 (예: "****")
}
```

**시각**:
- 인라인 사용: 🔒 아이콘 + 마스킹 텍스트
- 섹션 사용: 회색 박스 + 🔒 + 사유

**Flex 패턴 그대로**: Flex의 자물쇠 + UI 텍스트로 권한 노출 패턴 유지.

### 4-10. CommandPalette (⌘K 커맨드 팔레트) ⭐⭐ 차별화 P0

**역할**: 전역 검색 + 빠른 액션 + AI 자연어 명령 허브.

**Props**:
```tsx
type CommandPaletteProps = {
  isOpen: boolean;
  onClose: () => void;
}

// 내부 상태: 모드 (quick / employee / workflow_doc / workflow_create / ai)
```

**시각**:
- 화면 상단 중앙 (`top: 20%`, max-width 600px)
- 백드롭 (반투명)
- 입력창 + ⚡ 아이콘 (왼쪽) + ESC 힌트 (오른쪽)
- 결과 리스트 (모드별)
- 우측 하단 키보드 힌트 (`↑↓ navigate · ↵ select · esc close`)

**모드별 동작**:
1. **메인 (Empty)**: 빠른 액션 5개 + 최근 검색어
2. **할 일 요청**: 종류 선택 → 작성 진입
3. **구성원 검색**: 한국어 형태소 매칭 결과
4. **워크플로우 검색**: 결재 문서 검색
5. **워크플로우 작성**: 카테고리 칩 + 양식 리스트
6. **AI 자연어**: 모드 없이 자유 입력 시 자동 활성

**AI 명령 UX**:
- 사용자 입력 후 0.3초 대기 → Claude Haiku 호출
- 결과 확신도 (`confidence`) 표시:
  - >= 0.85: 자동 진입
  - 0.5~0.85: "다음으로 이동할까요? [예]" 확인
  - < 0.5: 모드 선택 화면 fallback

### 4-11. NotificationPanel (알림 패널) ⭐

**역할**: 헤더 벨 아이콘 클릭 시 드롭다운.

**Props**:
```tsx
type NotificationPanelProps = {
  notifications: Notification[];
  unreadCount: number;
  onRead: (id: string) => void;
  onReadAll: () => void;
  filter: 'all' | 'unread' | NotificationCategory;
  onFilterChange: (filter: string) => void;
}
```

**시각**:
- 헤더 우측 드롭다운 (380px 폭)
- 상단: "모든 알림" + 필터 칩 + "모두 읽음" 텍스트 버튼
- 리스트: 카테고리 아이콘 + 본문 + 시간 (`5분 전`)
- 미확인: 좌측 파란 점 마커
- 빈 상태: 벨 아이콘 + "확인되지 않은 알림이 없어요"

**Flex와 다른 점**:
- Flex는 단일 패널
- 우리는 **필터 칩 (전체 / 미확인 / 결재 / 휴가 / 시스템)** 빠른 전환
- 알림 클릭 시 `deep_link` 이동 + 자동 읽음

## 8. 인터랙션 / 모션

**원칙**: 절제. UX 보조 수준의 미세한 모션만.

```css
@theme {
  --duration-fast: 120ms;
  --duration-base: 200ms;
  --duration-slow: 300ms;

  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
  --ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);
}
```

**적용 위치**:
- 모달 진입: `opacity + scale(0.96 → 1)`, 200ms ease-out
- 드롭다운: `opacity + translateY(-4px → 0)`, 120ms ease-out
- 페이지 전환: 없음 (Next.js 기본)
- 호버: 색상 변화만, transform 없음

**금지**:
- ❌ 화려한 페이지 전환
- ❌ 큰 요소 fade/bounce 애니메이션
- ❌ 자동 재생 애니메이션 (사용자 트리거만)

## 11. 접근성 (a11y) 기본 원칙

- **모든 인터랙티브 요소에 키보드 접근 가능** (Tab 순서, Enter/Space 동작)
- **포커스 링 명시** (`shadow-focus` 토큰)
- **`aria-label`** 텍스트 없는 아이콘 버튼에 필수
- **`aria-live`** 동적 알림 (Toast 등)에 적용
- **색상에만 의존하지 않음** (status 칩에는 아이콘도 함께)
- **최소 명도 대비 4.5:1** (`text-slate-600` on `bg-white`는 7:1 — 안전)
