# 데이터 모델 초안

> HR 웹 프로젝트 - Flex 전체 분석 기반 데이터 모델 설계
> **최종 업데이트**: 2026.5.19 — **분석 완료**, User/Membership/Notification/Search/Message/Education 등 신규 추가
> 실제 구현 시 ORM/DB 선택에 따라 조정 필요

## 설계 원칙

1. **시점 기반 이력 관리** — 인사 데이터는 절대 UPDATE로 덮어쓰지 않음
2. **각 도메인별 별도 이력 테이블** — Flex 검증 패턴
3. **정책을 데이터로** — 휴가, 결재선, 양식, 권한 모두 코드에 박지 말고 DB에
4. **워크플로우 엔진 통합** — 휴가/결재/정보변경/공지/할일요청 모두 같은 인프라 (`FormDocument.document_kind`)
5. **멀티 테넌시** — `User` ↔ `Company` 다대다 (`UserCompanyMembership`), 모든 도메인 테이블에 `company_id`
6. **감사 로그 처음부터** — 모든 CUD 자동 기록 + 도메인별 메타데이터
7. **권한 시스템은 RBAC + Scope** — 행 단위 접근 제어

## 1. 회사 / 조직

```
Company (회사) — 싱글톤
├── id, 이름 (required)
├── 사업자등록번호 (XXX-XX-XXXXX)
├── 법인등록번호 (XXXXXX-XXXXXXX, 옵션)
├── 대표자_id → Employee
├── 대표 전화번호, 설립일
├── 주소 (도로명 + 상세)
├── 로고_url, 커버_url
└── 직인_url (P2)

Department (부서)
├── id, company_id, 부모_id (계층)
├── 이름, 정렬 순서
└── 활성 여부

DepartmentHistory (조직 변경 이력) — 시점 기반
├── department_id
├── effective_date (적용일)
├── 변경 유형 (신설/이름변경/이동/폐지)
├── 변경 내용 (JSON: before/after)
├── 변경자_id, 메모
└── appointment_id → Appointment (FK)
```

## 4. 휴가 — 대폭 강화 ★★

### LeavePolicy (연차 정책) — 회사당 N개, 직원에게 할당

```
LeavePolicy
├── id, company_id
├── 이름, 설명
├── effective_from (부여 시작일) ★ 정책 자체가 시점 기반
│
├── [기본 설정]
│   ├── approval_policy_id → ApprovalPolicy
│   ├── 사용 단위 (time / half_day / full_day)
│   ├── 등록 시 승인 (bool) ★
│   ├── 취소 시 승인 (bool) ★
│   └── 당겨쓰기 (none / limited:N / unlimited)
│
├── [부여 모드] ★★ 최상위 분기
│   ├── grant_mode (fiscal_year / hire_date)
│   ├── fiscal_start_month (1~12, fiscal_year 모드 시)
│   │
│   ├── [입사자 월차 부여 정책]
│   │   └── monthly_grant_rule (enum)
│   │       - monthly_on_attendance (매월 개근시 1일, 추천)
│   │       - lump_sum_on_hire_11 (입사일 11일 선부여)
│   │       - lump_sum_until_fiscal (회계일까지 선부여, fiscal_year만)
│   │
│   ├── [입사자 1년 만근 연차 정책]
│   │   └── annual_first_year_rule (enum)
│   │       fiscal_year 모드:
│   │       - 15_on_first_fiscal (첫 회계일 15일)
│   │       - prorated_on_first_fiscal (비례 부여, 추천)
│   │       - lump_sum_until_fiscal
│   │       hire_date 모드:
│   │       - 15_on_anniversary (1년 만근시 15일, 추천)
│   │       - lump_sum_on_hire_15
│   │
│   └── [소수점 처리]
│       └── decimal_rule (round_up_day / round_up_half / no_adjustment)
│
├── [자동 소멸 설정]
│   ├── 월차 소멸 시점 (none / 1y_from_hire / 1y_then_fiscal)
│   ├── 월차 소멸 유예 (0~24개월)
│   ├── 연차 소멸 시점 (none / 1y_from_grant)
│   └── 연차 소멸 유예 (0~24개월)
│
└── [스마트 연차 촉진]
    ├── enabled (bool)
    ├── 연차 촉진 시점 (소멸 N개월 전, 1년+ 재직자)
    ├── 월차 1차 시점 (소멸 N개월 전, 1년 미만)
    └── 월차 2차 시점

CompanyLeaveSettings (회사 단일) ★ 신규
├── company_id
├── retiree_adjustment_rule (favor_employee / strict_legal)
└── default_promotion_settings
```

### LeaveType (맞춤 휴가) — 6가지 부여 방식 ★★

```
LeaveType
├── id, company_id
├── 이름, 설명, 아이콘
├── is_system (시드 데이터 여부)
├── is_required (필수, 삭제 불가) — 법정 8종은 true
│
├── [부여 정책]
│   ├── grant_method (enum):
│   │   - on_request           (신청 시 부여)
│   │   - on_other_exhausted   (연차 소진 시 부여)
│   │     └── linked_leave_type_id → LeaveType
│   │   - manual               (관리자 직접)
│   │   - on_hire              (입사 시)
│   │   - periodic             (반복 부여)
│   │     ├── period (monthly / yearly)
│   │     └── days
│   │   - on_tenure            (근속 시)
│   │     └── tenure_years (3년차, 5년차 등)
│   ├── grant_unit (minute / hour / day / unlimited)
│   └── grant_amount (number, unlimited 시 N/A)
│
├── [사용 정책]
│   ├── consumption_mode (all_at_once / divisible)
│   └── divisible_units (day, half_day, hourly)[]
│
├── [급여]
│   └── payment_type (paid / unpaid / partial_paid)
│       └── partial_paid_config (JSON, 비율/일수)
│
├── [승인]
│   └── approval_policy_id → ApprovalPolicy
│
└── [추가 설정] ★ 신규
    ├── gender_restriction (all / male / female)
```

## 18. 벌크 작업 인프라 ★ 신규 (AxHub bulk 대응)

### 설계 의도
- **MVP (현재)**: 수기 단건 입력 + **CSV 일괄 업로드** (HR이 직접)
- **AxHub 연동 후**: 동일 인프라 위에서 **API bulk sync** (자동 동기화)
- 두 흐름 모두 **같은 처리 파이프라인** 통과 → 검증/롤백/이력이 일관

### 처리 파이프라인 (공통)
```
[입력] → [파싱·검증] → [미리보기·충돌 해결] → [확정 실행] → [결과·롤백 옵션]
   ↑                                                            ↓
수기 CSV / AxHub API                              BulkOperationLog 기록
```

### 충돌 해결 전략 (Conflict Resolution)

CSV/AxHub 데이터가 기존 Employee와 충돌할 때:

| 충돌 유형 | 감지 키 | 해결 옵션 |
|---|---|---|
| 동일 이메일 존재 | `email` | 업데이트 / 스킵 / 새로 생성(거부) |
| 동일 사번 존재 | `employee_number` | 업데이트 / 스킵 / 에러 |
| 동일 `axhub_external_id` | `axhub_external_id` | 업데이트 (정상) |
| `sync_locked_fields` 수기 수정 시도 | UI 차단 | 사용자에게 "AxHub에서 관리 중" 안내 |

### MVP에서의 동작 (수기 + CSV)
- HR이 `/members` 페이지 → **"+ 일괄 가져오기"** 클릭
- CSV 업로드 → `BulkOperation(csv_import_employees)` 생성
- 백그라운드 잡이 파싱·검증 → `status=awaiting_confirm`
- HR이 `/members/bulk-import/[id]` 미리보기 → 충돌 해결 → 확정
- 실행 → `BulkOperationRow` 라인별 처리
- 결과 표시 + 24시간 내 롤백 가능

### AxHub 연동 후의 동작 (자동)
- AxHub Webhook 또는 스케줄러가 `BulkOperation(axhub_sync_*)` 자동 생성
- 동일 검증 파이프라인 통과
- `conflict_strategy`에 따라 자동 처리 또는 HR 검토 대기
- 검토 필요 시 알림 발송 (`Notification.category = 'system_security'`)

### 권한
- `member.bulk_import` — CSV 일괄 가져오기 권한 (HR 권한자)
- `member.bulk_export` — CSV 일괄 내보내기 권한
- `integration.axhub.sync` — AxHub 동기화 설정·실행 권한 (최고 관리자)

### User vs Employee 관계
- **User** = 인증 단위 (사람 한 명, 회사 무관, 멀티 테넌시 루트)
- **Employee** = 특정 회사에서의 직원 신분 (회사 N개 소속 가능)
- **UserCompanyMembership** = 다대다 + 멤버십 상태

→ 한 사람이 회사 A와 B 모두에 가입 시 `User` 1개, `Employee` 2개, `Membership` 2개
