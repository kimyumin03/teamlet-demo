## 1. 홈 피드

### 구조
- **3-column 레이아웃**: 좌측 사이드바 + 중앙 콘텐츠 + 우측 위젯
- 3개 메인 탭: **홈 피드 / 회사 소식 / 할 일**

### 핵심 기능

**홈 피드 / 회사 소식**
- 공지사항, 인정 통합 피드
- 회사 차원 정보 허브

**할 일 (워크플로우 진입점)**
- 3분할: **해야 할 일 / 요청한 일 / 참조** ← Jira/Asana 표준 패턴
- 상태 색상 4가지: 대기(흰)/진행(반쪽 초록)/완료(파란 체크)/반려(빨간 금지)

**동료에게 전달하기 (메인 액션 허브)**
1. 공지사항 작성하기 (코랄)
2. 할 일 요청하기 (초록)
3. 작성 요청하기 (청록) — 문서 양식 채워달라
4. 인정 메시지 보내기 (보라)
5. 피드백 메시지 보내기 (회색)

### 적용 포인트
- 워크플로우 3분할 (해야할일/요청한일/참조) 표준 적용
- 상태 코드 4가지 색상+아이콘 일관 적용
- Empty State 디자인을 처음부터 고려

## 2. 구성원 (Core HR)

### 3개 메인 탭
```
구성원
├── 구성원 (직원 리스트)
│   ├── 전체 / 입사 / 퇴사 / 초대 현황
├── 조직도 (시각적 트리)
└── 인사 정보 관리 (이력/일괄변경)
```

### 핵심 개념: 시점 기반 조회

- **"기준일" 필터**: 단순 "지금 누가 재직중" X, **"X월 X일 기준"** 조회
- 분기별 인원 통계, 과거 시점 조직 조회 등에 필수
- 인사 발령 = 새 이력 row 추가, 본체 UPDATE X

### 5종 분류 체계 (헷갈리기 쉬움)

| 분류 | 영문 | 예시 |
|---|---|---|
| 직군 (Job Family) | 큰 분류 | 개발, 디자인, 마케팅 |
| 직무 (Job) | 세부 일 | 백엔드, 프론트엔드, AI |
| 직위 (Position) | 호칭/연차 | 사원, 대리, 과장 |
| 직급 (Grade) | 내부 등급 | G1, G2, G3 (민감 정보) |
| 직책 (Role) | 조직 내 역할 | 팀장, 본부장 |

→ 회사가 일부만 써도 작동해야 함. 다 옵션.

### 구성원 추가 흐름

**점진적 공개 폼:**
```
[필수] 기본정보 입력
[선택] 인사 정보 입력      ← 토글
[선택] 근로계약 정보 입력   ← 토글
[선택] 임금계약 정보 입력   ← 토글
```

진입장벽 최소화: "이름/이메일/입사일만 있으면 초대 가능"

### 적용 포인트
- **시점 기반 인사 이력 테이블 필수** (가장 중요)
- 직급은 권한 분리 처음부터
- CSV import는 빨리 추가 (데모 데이터 용)

## 3. 구성원 상세 페이지 (프로필)

### 페이지 구조 (이미지 1)

**상단 영역**
- 커버 이미지 (그라데이션, "커버 편집" 버튼)
- 큰 컬러 아바타 (이니셜 자동 생성, 사용자 지정 가능)
- 이름 + 직무·조직 (없으면 "직무 · 조직 없음")
- 우측: 다운로드 버튼, 전체화면 토글, 닫기

**상단 탭 5개**
- **정보** (메인) / 성장 / 교육 / 문서·증명서 / 인사노트

**우측 상단**
- ⏱ **정보 변경 내역** 버튼 ⭐ (시점 이력 조회 진입점)

### 정보 탭 — 좌측 메인 콘텐츠 (이미지 1~4)

긴 폼 형식, 섹션별 그룹화:

```
1. 인사 정보 (+ 추가)         ← 발령 트랜잭션 작성
2. 기본 정보 (✏ 변경)         ← 이름/이메일/입사일/주민번호/연락처/주소
3. 근로 계약 정보 (+ 추가)
4. 임금 계약 정보 (+ 추가)
5. 급여 지급 정보 (+ 추가) 🔒  ← 자물쇠 = 민감
6. 근무 정보 (✏ 변경)         ← 시점: "2026.5.18 ~ 현재"
7. 초과 근무 보상 정보 🔒
8. 휴가 정보 (연차 정책)
9. 쉬는 날 정보
10. 휴직 이력 (+ 추가)
11. 수상 (+ 추가)
12. 징계 (+ 추가)
13. 경력 정보 (+ 추가)
14. 학력 정보 (+ 추가)
15. 특이사항 (✏ 변경)
16. 가족 정보 (+ 추가)
    └── 총 공제 대상 (기본 공제 N명, 건강보험 피부양자 N명)
```

각 섹션에 **"+ 추가"** 또는 **"✏ 변경"** 액션. 시점 기반 데이터는 우측 상단에 **"2026.5.18 - 현재"** 시점 표시.

### 정보 탭 — 우측 사이드 (이미지 1~4)

**프로필 카드**:
- 내 소개 작성하기 (자유 텍스트)
- 📞 휴대전화 / ✉ 이메일 / 🏢 조직 / 📍 주소 / 💼 근무유형 (각각 "없음" 가능)
- ⏱ 근무한 시간 / 🏖 보유한 연차 (요약 지표, 클릭 시 상세 페이지)

**섹션 점프 칩**:
```
다음으로 이동...
[인사] [기본] [근로 계약] [임금 계약] [급여 지급]
[근무] [초과 근무 보상] [휴가] [쉬는 날] [휴직 이력]
[수상] [징계] [경력] [학력] [특이사항] [가족]
```
→ 긴 페이지의 빠른 네비게이션 패턴

### 인사 정보 추가 모달 (이미지 5) = 발령 트랜잭션

**상단 칩**: `적용일 오늘` `발령 라벨` `메모` (확장 옵션)

**필드 (2-column)**:
- 직무 / 직군 / 직위 / 직급 (드롭다운)
- 조직 · 직책: 조직 선택 + 조직장 체크박스 + 직책 선택
- "조직 추가" 버튼 (다중 조직 소속 지원)
- 안내문: "최상단에 노출되는 조직이 주조직으로 설정돼요"

### 기본 정보 변경 모달 (이미지 6~9)

**Left**: 폼
```
- 이름 *
- 영문 이름 (성/이름 분리)
- 이메일 (회사) *
- 개인 이메일
- 닉네임
- 사번
- 입사일 *
- 그룹 입사일 * (토글: "그룹 입사일 사용하기" 신규)
- 입사 유형 (드롭다운)
─────────────
- 주민등록번호 (외국인등록번호 호환)
- 생년월일
- 휴대전화번호 (국가코드 +82 선택)
- 국적 / 거주국가 / 체류자격 (외국인 비자)
- 집 주소
- 급여 계좌 (은행 + 계좌번호 + 실명인증 버튼)
- 장애인 · 국가유공자 (드롭다운)
```

**Right (사이드 패널 토글)**: 승인·참조
- "승인자가 설정되지 않아서 자동으로 완료돼요" 경고 (이미지 7)
- 참조 / 1단계 승인 (이전 결재 UI 재사용)

### 근무 정보 변경 모달 (이미지 1)

- 상단: **`적용일 오늘`** 칩 ⭐ (시점 기반 표준)
- 회사 마스터의 근무 유형 중 라디오 선택
- 카드 정보: 출근시간 / 주 근무시간 / 쉬는 날
- 우측 상단 **⚙ 톱니바퀴** = 결재선 진입점

### 근무 유형 상세 (읽기 전용, 이미지 2)
```
근무유형: 고정 근무유형
일하는 날: 월,화,수,목,금
주휴일: 일요일
일하는 시간: 8시간 [주 40시간]
출근 시각: 오전 9:00
```

### 정보 변경 내역 페이지 ⭐⭐ (이미지 3, 4)

**URL/페이지**: 구성원 상세 → 우측 상단 "정보 변경 내역" 클릭

**상단 탭 6개** (각 도메인별 별도 이력):
- 인사 정보 / 근로 계약 정보 / 임금 계약 정보 / 급여 지급 정보 / **근무 정보** / **초과 근무 보상 정보**

**테이블 컬럼 예시 (근무 정보)**:
| 적용일 | 근무 유형 | 일하는 방식 | 일하는 날 | 일하는 시간 | 변경 정보 |
|---|---|---|---|---|---|
| 2026.5.18 [현재] | 샘플 근무유형 | 고정 근무유형 | 월~금 | 40시간 | 2026.5.18 오후 7:... |

**테이블 컬럼 예시 (초과 근무 보상)**:
| 적용일 | 초과 근무 보상 정책 | 포괄 계약 공제 주기 | 변경 정보 |
|---|---|---|---|
| 2026.5.18 [현재] | 기본 초과 근무 보상 정책 | 매달 1일 - 매달 31일 (말일) | 2026.5.18 오후 7:00 · 송재희 |

**우측 액션**: 정렬 / "+ 내역 추가하기"

### 휴가/쉬는 날 변경의 retroactive 경고 (이미지 7, 8)

**중요한 UX 패턴 — 데이터 변경의 후행 영향 명시**:
- 연차 정책 변경: ⚠ "연차 정책을 변경할 경우, 입사일 이후부터 다시 집계되니 신중하게 변경해주세요"
- 쉬는 날 변경: ⚠ "쉬는 날을 변경하면 이미 지나간 쉬는 날도 모두 변경돼요"

→ 변경이 과거 데이터까지 재계산하는 작업은 명시적 경고

### 톱니바퀴(⚙) = 결재선 진입점 (통일 패턴)
- 거의 모든 변경 모달 우측 상단에 ⚙
- 클릭 → 결재선 설정 (참조/승인)
- 우측 사이드 패널로 펼침 (또는 별도 모달)

### 적용 포인트

1. **각 도메인별 별도 이력 테이블** — Flex가 검증한 패턴
   - `PositionHistory` / `EmploymentContractHistory` / `SalaryContractHistory` / `WorkTypeAssignmentHistory` / ...
2. **모든 변경 모달에 적용일 칩 + 결재선 진입점** 표준화
3. **"정보 변경 내역" 페이지**를 도메인 탭으로 분리
4. **외국인 직원 지원** — 외국인등록번호, 거주국가, 체류자격
5. **세제 특화 필드** — 장애인·국가유공자, 총 공제 대상, 건강보험 피부양자
6. **점프 칩** — 긴 폼의 섹션 네비게이션
7. **다중 조직 소속** — 주조직 + 부조직

### 미완료 분석 (남은 작업)

- 근로 계약 / 임금 계약 / 급여 지급 추가 모달
- 휴직 이력 / 수상 / 징계 / 경력 / 학력 / 특이사항 / 가족 추가 모달
- 성장 / 교육 / 문서·증명서 / 인사노트 탭

## 4. 휴가

### 3개 서브 탭 (내 휴가 시점)
- 휴가 개요 / 연차 상세 / 연차 사용 계획

### 휴가 카드 8종 (예시)

| 휴가 종류 | 부여 방식 | 분류 |
|---|---|---|
| 연차 | 누적 부여형 | 매월 +1일 |
| 가족돌봄 | 신청시 부여형 | 1일 |
| 군소집훈련 | 신청시 부여형 | - |
| 난임 치료 | 정기 부여형 | 매년 6일 |
| 결혼-본인 | 신청시 부여형 | 5일 |
| 리프레시 | 조건부 부여형 | 3년 근속 시 30일 (자물쇠) |
| 병가 | 연계 부여형 | 연차 소진시 60일 |

### 부여 정책 — 연차 전용 (회계장부 패턴)

```
| 자동 부여 (초록) | 소멸 (빨강) | 사용 (노랑) | 조정 (보라)
|     +7일         |    없음     |    없음     |    없음
```

→ 연차를 "재고"로 보고 입출고 회계. 차변/대변 개념.

### 연차 사용 촉진제도
한국 노동법 특수 제도. 회사가 직원의 연차 소진을 권장해야 하고, 안 그러면 미사용 연차 수당 지급 의무.

### 한국 노동법 디테일

| 항목 | 규칙 |
|---|---|
| 입사 1년 미만 | 매월 만근 시 1일 (최대 11일) |
| 1~3년 미만 | 연 15일 |
| 3년 이상 | 2년마다 +1일 (최대 25일) |
| 휴가 단위 | 일/반차(4시간)/시간(1시간) |

### 적용 포인트
- **휴가 정책 엔진을 데이터로** (코드에 박지 말 것)
- LeaveTransaction은 immutable 회계장부
- MVP는 "월 1일 부여, 연 15일 상한"부터
- **연차와 맞춤 휴가는 별도 엔진** (설정 분석에서 확정)

## 5. 채용

### 3개 메인 탭
```
채용
├── 후보자 (지원자 풀)
│   ├── 전형 진행 중 / 전형 종료
├── 공고 (포지션 관리)
└── 사이트 (외부 채용 페이지 빌더)
```

### 워크플로우 의존 구조
```
사이트 만들기 → 공고 작성 → 후보자 지원 → 전형 진행 → 채용 확정
```
→ **공고 없이는 후보자 등록 불가**. 후보자는 반드시 공고와 연결.

### 공고 작성 3단계 탭
```
1. 공고 본문    ← 리치 텍스트
2. 전형 단계    ← 서류/1차/2차/최종
3. 지원 정보    ← 지원자가 입력할 양식
```

### 사이트 빌더 (제외 영역)
- AI로 30초 만에 채용 사이트 생성
- 직접 만들기 (PC/모바일 토글, 드래그 빌더)
- 평가 템플릿 / 이메일 템플릿 / 일정 추천

### Flex 수익화 관찰
- "6월 1일부터 채용 무료 버전 종료" 공지
- 채용은 **별도 유료 모듈** — 코어 외 부가 기능

### 적용 포인트
- 사이트 빌더 제외 (P3 이상)
- 평가 템플릿 데이터 모델만 미리
- 후보자 - 공고 연결 강제 (Flex 따라가기)

## 6. 워크플로우 + 양식 빌더

### 메뉴 구조
```
워크플로우
├── 내 문서함 (본인 작성)
├── 회사 문서함 (전사, 권한자만)
├── 문서 양식 관리

```

### 양식 분류 (예: 13개)
- 구매 신청 (비품, 계정)
- 복리 후생 (경조비, 식비)
- 비용 처리 (출장비, 식비)
- 계약 (계약서 검토)

**휴가는 별도 메뉴** — 양식 분류 "휴가"는 0개. Flex는 휴가를 UX상 분리하지만 내부적으론 동일 엔진.

```
좌측: 양식 본문 (필드 + 자유 본문)
우측: 결재선 (참조 / 1단계 승인 / 추가 단계)
```

### 결재자 권한 종류
- 승인 (실제 결재 권한)
- 참조 (보기만, 알림)
- 검토/합의/전결 (한국 결재 문화)

### 양식 빌더 핵심

**필드 타입:**
- Tt 텍스트 / 1 숫자 / ₩ 금액 / 📅 날짜 / ☑️ 선택 / 📎 파일

**옵션:**
- 참고 파일 (양식 첨부 가이드)
- 첨부 파일 허용 (작성자가 첨부)
- 내용 (리치 텍스트 본문)

**결재선 옵션 (전사 표준 패턴):**
- **요청자별 승인** — 작성자 부서 따라 결재자 달라짐
  - ON 시 UI: 기본 설정 / 설정 추가하기 (조건별 결재선)
- **변경 허용** — 작성자가 결재선 수정 가능

### 적용 포인트
- **MVP: 휴가 양식만 하드코딩**, 양식 빌더는 P2
- 데이터 모델은 처음부터 양식 정의 기반
- 결재 처리는 트랜잭션 모델 (immutable 액션 로그)

## 9. 설정 — 휴가 그룹

### 9-1. 연차 설정 ⭐⭐ (정책 엔진의 심장)

#### 페이지 구조
1. **연차 정책** (리스트, N개 가능, "+ 연차 정책 추가")
2. **퇴직자 연차 조정 기준 설정** (회사 단일)
3. **연차 촉진 설정** (회사 단일 기본값)

#### 핵심 발견 1: "회계일 vs 입사일" 이중 모드

**회계일 모드**
- 모든 직원에게 같은 날 일괄 부여 (예: 매년 1월 1일)
- ⚠ 취업규칙에 회계연도 기준 명시 필수 (법적 요건)
- ⚠ 퇴직 시 입사일 기준으로 재계산하여 정산 필요 (이중 계산 의무)
- 회계일 시작월 선택 (1~12월), **1월 1일이 95% 회사 사용** (데이터 인사이트 노출)

**입사일 모드**
- 각자 입사일 기준으로 따로 부여
- 관리 복잡, 자동화 의존도 높음

#### 핵심 발견 2: "월차 vs 연차" 이원 회계

| 구분 | 대상 | 부여 패턴 | 법적 근거 |
|---|---|---|---|
| 월차 | 입사 1년 미만 | 매월 만근 시 1일 (최대 11일) | 근로기준법 60조 2항 |
| 연차 | 1년 이상 | 연 단위 일괄 (15~25일) | 근로기준법 60조 1항 |

→ 단일 LeaveBalance로 표현 불가. **월차/연차 별도 트랜잭션 카테고리**.

#### 입사자 월차 부여 방식 (회계일 모드 기준 3개)
| 옵션 | 의미 |
|---|---|
| ✅ 매월 개근시 1일 부여 (추천) | 법정 기본 |
| 입사일에 11일 선부여 | 일괄 |
| 입사일에 회계일까지의 월차 선부여 | 입사~다음 회계일까지만 |

#### 입사자 1년 만근 연차 부여 방식 (회계일 모드 기준 3개)
| 옵션 | 의미 |
|---|---|
| 첫 회계일에 15일 부여 | 일수 비례 무시 |
| ✅ 첫 회계일에 근무한 기간의 연차 부여 (추천) | **비례 부여** |
| 입사일에 회계일까지 연차 선부여 | 입사 시점 일괄 |

#### 소수점 이하 연차 처리
- ✅ 일 단위 올림 (추천) / 반차 단위 올림 / 조정 안 함
- "조정 안 함" 선택 시 안내: ⚠ "소수점 이하 휴가는 임의로 공제할 수 없으며, 사용되지 않은 만큼 수당으로 지급해야 해요"

#### 부여 시작일 + 자동 부여 미리보기
- 정책 자체가 시점 기반 (effective_from)
- **미리보기 테이블**: 미리보기 날짜 / 월차 / 연차 (자동 시뮬레이션)
- 캘린더 위젯으로 날짜 변경 가능

#### 자동 소멸 설정 (월차/연차 각각)

**월차 자동 소멸 시점**:
- 소멸 안 함 / ✅ 입사일로부터 1년 후 / 입사일로부터 1년 후 첫 회계일

**연차 자동 소멸 시점**:
- 소멸 안 함 / ✅ 부여일로부터 1년 후

**소멸 유예 기간**:
- 유예기간 없음 / 1~24개월 (드롭다운)
- 법정 소멸일 이후 추가 사용 가능 기간 (직원에게 유리한 정책 도구)

#### 퇴직자 연차 조정 기준
- ✅ 구성원에게 유리한 기준 (기본) — max(법정, 회사부여)
- 항상 근로기준법 기준 — 회사 부여량 무시
- 예시 표로 비교 (UX)

#### 연차 촉진 설정
**일반**: 승인·참조자 / 구성원 작성 리마인드 / 관리자 작성 리마인드 / 사용 계획일 알림 시점

**⭐ 스마트 연차 촉진** (법정 자동화):
| 항목 | 의미 |
|---|---|
| 연차 촉진 시점 | 소멸 N개월 전 (1년 이상 재직자) |
| 월차 1차 촉진 | 소멸 N개월 전 (1년 미만) |
| 월차 2차 촉진 | 소멸 N개월 전 (1년 미만) |

#### 옵션 칩 동작 (이미지 16~18 검증)
- **요청자별 승인** ON → 결재선이 "기본 설정 / 설정 추가하기"로 변경 (조건별 분기)
- **변경 허용** ON → 작성자가 신청 시 결재선 직접 수정 가능
- 두 옵션 독립적

### 9-2. 맞춤 휴가

#### "필수 휴가" 시드 8종 (삭제 불가)

| 휴가 | 기본 결재선 |
|---|---|
| 가족돌봄 | 승인 없음 |
| 군소집훈련 | 1단계 + 참조 1 |
| 난임 치료 | 1단계 + 참조 1 |
| 배우자출산 | 1단계 + 참조 1 |
| 보건 (생리휴가) | 1단계 + 참조 1 |
| 보상 | 승인 없음 |
| 산전후 - 본인 | 1단계 + 참조 1 |
| 산전후 - 미숙아 | 1단계 + 참조 1 |

→ 수정은 가능, 삭제만 불가 ("필수 휴가는 삭제할 수 없어요")

#### 부여 방법 6가지 (드롭다운 2 카테고리)

**A. "조건에 따라 부여" (이벤트 트리거)**
- ✅ 신청 시 부여
- 연차 소진 시 부여 (linked_leave_type_id 필요)
- 관리자가 직접 부여
- 입사 시 부여

**B. "주기 단위로 루틴하게 부여" (시간 트리거)**
- 반복 부여 (월/연 N일)
- 근속 시 부여 (N년차 도달)

**⚠️ 중요**: 연차의 "누적 부여(매월 +1)"는 맞춤 휴가에 없음. **연차 전용 엔진**.

#### 부여 단위
- 분 단위 / 시간 단위 / ✅ 일 단위 / **신청하는 만큼 부여** (⚠ 경고문구)

#### 사용 단위 (사용 방식)
**한번에 모두 사용** — ⚠ "나머지 휴가는 자동 소멸됩니다"
**나눠서 사용** — 일 / 반차(오전·오후) / 시간차 설정

#### 급여 지급 유무
- 유급 / 무급 / 일부 유급 (비율·일수 설정)

#### 추가 설정 4종

| 옵션 | 값 |
|---|---|
| 사용 가능 성별 | 모두 / 남성 / 여성 |
| 증명 자료 제출 | 없음 / 사전 제출 / 사후 제출 |
| 제외 대상 설정 | 근로유형/조직/구성원 선택 |
| 휴일에 등록된 휴가 차감 | 토글 |

#### 근로 유형 8종 (제외 대상 등에서 발견)
**정규직 / 계약직 / 파견직 / 일용직 / 프리랜서 / 등기 임원 / 비등기 임원 / 위촉직**

### 10-1. 로그인 설정 (`beta`)

#### 비밀번호 복잡도
- **기본 설정 (고정)**: 최소 8자, 영문+숫자+특수문자 모두 (변경 불가)
- 보안에 취약한 비밀번호 체크 (전세계 자주 사용 PW Top 30)
- 개인정보 체크 (성명/생일/이메일/주민번호 포함 여부)
- 최근 사용 비밀번호 체크 (1~5개)

#### 비밀번호 유효 기간
- 변경 주기: 미설정 / 30 / 60 / 90 / 180 / 360일
- 만료 전 이메일 알림 시점

#### 로그인 실패시 잠금
- 시도 횟수: 3 / 5 / 10회

#### 자동 로그아웃 (디바이스별 분리 ⭐)
- **PC**: 3시간 / 6시간 / 12시간 / 1일 / 3일 / **7일** (기본) / 14일
- **모바일**: 30 / 90 / 180 / **365일** (기본)
- → PC는 짧게(보안), 모바일은 길게(UX)

#### 구성원 로그인 관리
- 휴직자 로그인 허용 (토글, 기본 OFF 권장)
- 임시 비밀번호 발급 (인사담당자 액션)

### 10-2. 보안·인증 설정

#### 2단계 인증
- 마스터 토글 (전사 강제)
- **2FA 제외 IP** — 사무실 IP에서는 OTP 스킵
  - **CIDR 표기법 지원** (예: 192.168.1.0/24)
  - **"현재 접속 IP 추가"** 버튼 (락아웃 방지)
  - ⚠ "접근 허용할 IP 주소를 반드시 등록해야 설정이 저장돼요"
- 구성원 OTP 재설정 (관리자 액션, 기기 분실 시)

#### 특정 IP에서만 접근 허용 (완전 화이트리스트)
- 접근 허용 IP (전체 차단)
- 기능 제한 범위 설정 (소프트 차단, 허용 IP 외 접속 시 일부만 제한)
- 최고 관리자 적용 (토글, 기본 OFF 권장 — 백도어 확보)

#### Flex에 없는 것 (참고)
- SSO/SAML, AD/LDAP 없음 → AxHub가 IdP 역할 가능성
- SMS/Email OTP 없음
- WebAuthn/Passkey 없음

### 10-3. 감사 로그 (`beta`)

#### 필터 6종
- **활동 유형**: 개인정보 접근 / 인증 / 권한 변경
- **사용자** (검색 + 조직도 보기, 하위 조직 함께 선택)
- **이벤트**: 다운로드 / 생성 / 조회 / 수정 / 삭제
- **정보 유형** (3 그룹 × 다수, 검색 가능):
  - 개인정보: 개인정보/특이사항/가족정보/학력/경력/자격/기타
  - 소득정보: 사업소득/근로소득/퇴직소득/기타소득/기타
  - 인사정보: 인사정보/평가정보/채용정보/기타
- **기간**: 최근 7일 (기본) / 14·30·90일 [엔터프라이즈] / 직접입력
- **권한 위임**: 해당 / 해당 안 함

#### 로그 컬럼
- 활동유형(배지) / 사용자 / 이벤트 / 정보유형 / 상세설명·사유 / 날짜(초 단위) / IP

#### 로그 상세 (우측 패널)
- 위 컬럼 + **변경 내용 JSON 노출**:
```json
{
  "features": ["ALL"],
  "ips": [],
  "enabled": false
}
```

#### 다운로드
- CSV 파일, 비동기 처리 ("요청" 표현)

#### 핵심 인사이트
- 감사 로그가 **정보 분류 체계** 보유 (data classification)
- 미들웨어만으로 부족 → **하이브리드** (raw 자동기록 + 도메인별 풍부한 메타데이터)
- "조회"도 로깅 (단, 민감 정보만 권장)

## 11. 설정 — 권한 / 연결

### 11-1. 권한 설정 ⭐ (재설계됨)

#### 2개 모드
- **권한 그룹** 탭 — 역할 정의 (RBAC)
- **구성원 권한** 탭 — 사용자 기반 조회 (디버깅용 양방향)
- 구성원 권한에서 권한 그룹 클릭 → 그룹 편집 페이지로 점프

#### 권한 그룹 3 종류 (+ 사용자 정의 N)
| 그룹 | 성격 |
|---|---|
| 최고 관리자 (👑) | 시스템 제공, 모든 권한, 멤버 명시 |
| **조직장** | **동적 역할** — 조직장 임명되면 자동 부여 |
| 기본 권한 | 모든 구성원 공통 |
| (사용자 정의) | + 권한 그룹 추가 (N개) |

→ "조직장" 동적 역할은 `PositionHistory.is_organization_head = true`인 사람에게 자동 매핑

#### 권한 카테고리 14개
1. 회사 정보
2. 구성원 개인 정보
3. 구성원 인사 정보
4. 근무 (우리는 제외)
5. 휴가
6. 자동 발송
7. 워크플로우
8. 승인
9. 급여정산 (제외)
10. 인사 회계 (제외)
11. 공지사항
12. 인정과 피드백
13. 외부 서비스 연동
14. 인사이트 (제외)
15. 보안
16. 구독·결제 (제외)
17. 감사 로그
18. 단체 보험 (제외)
19. 권한
20. 채용 (별도 페이지 안내만)

#### 권한 패턴: "조회 / 관리" 페어
거의 모든 데이터 영역에 조회·관리 2단계 권한:
```
구성원 개인 정보 조회 ← READ
구성원 개인 정보 관리 ← READ + WRITE (편집/변경승인/다운로드)
```
약 18쌍 = 36개 권한 + 기타 = 총 ~70개

#### "전체 구성원" 범위 토글 ⭐⭐
거의 모든 구성원 관련 권한에 적용 범위 옵션:
- 전체 구성원 / 특정 조직 / 본인 직속 부하 / 본인만

→ **RBAC + Scope = ABAC에 가까운 하이브리드**

#### ⚠ 민감 정보 경고 표시
일부 권한에 "주의: 권한 부여 시 급여 등 민감 정보가 노출될 수 있으니 주의해주세요":
- 회사 조직도 트렌드 조회
- 인사이트 조회
- 구성원 정보 포함 조회

#### 권한 그룹 편집 UI (2-column)
- 좌측: 카테고리 탭 + 권한 체크박스 + 검색
- 우측: 권한 그룹 구성원 (추가/삭제)
- 카테고리 탭은 **가로 스크롤** (14개)

### 11-2. 연결 설정 (단순)

#### 외부 서비스 연동 2개만
- **Slack** — 출/퇴근 기록, 워크플로우 승인, 휴가 사용 알림
- **Google Calendar** — 근무/휴가 일정, 채용 인터뷰 일정

#### 우리 적용

## 13. 공통 디자인 패턴

### 1) 점진적 공개 (Progressive Disclosure)
- 필수만 처음 보이고, 나머진 토글
- 진입장벽 최소화

### 2) 칩 기반 메타데이터
- 라벨+인풋 대신 칩으로 간결하게
- 필터, 상태, 옵션 모두 칩

### 3) 그라데이션 메인 CTA
- 초록→청록 그라데이션
- 페이지당 1개만, 강한 시각적 우선순위

### 4) 우측 사이드 패널
- 복잡한 액션엔 메인+사이드 2-column
- 단순 액션엔 단일 컬럼

### 5) 위저드 네비게이션
- 페이지 하단 "이전/다음으로" 카드
- 사이드바 의존 X, 순차 진행 유도

### 6) 권한 정보 명시
- 🔒 자물쇠 + "본인 + 인사권한자만 볼 수 있어요"
- UI 텍스트로 권한 직접 노출

### 7) 시점 기반 변경
- **"적용일" 칩 (주황색)** 으로 시점 명시
- 모든 인사 데이터 변경의 표준 패턴
- 변경 모달 우측 상단 ⚙ 톱니바퀴 = 결재선 진입점

### 8) AI를 진입장벽 낮추는 도구로
- 채용 사이트 30초 생성
- 회사 직인 자동 생성
- "디자이너 없이 OK" 메시지

### 9) 미저장 변경 가드 (Dirty State Guard) ⭐
- 변경 후 미저장 상태에서 이탈 시도하면 모달 차단
- **Primary: "나가기" (코랄/주황, destructive 색상)**
- Secondary: "이어서 진행하기" (텍스트 버튼)
- 표준 그라데이션 색상 사용 X → 위험 액션 구분
- 적용 범위: 모든 설정 모달, 인사 정보 편집, 양식 빌더 등

### 10) Retroactive 영향 경고 ⭐
- 데이터 변경이 과거까지 재계산되는 경우 명시
- 예: 연차 정책 변경 → "입사일 이후부터 다시 집계되니 신중하게"
- 예: 쉬는 날 변경 → "이미 지나간 쉬는 날도 모두 변경돼요"

### 11) 데이터 인사이트 노출
- 옵션 옆에 "95%의 회사가 사용하고 있어요" 같은 사용 통계
- 사용자 결정 가이드

### 12) 미리보기 / 시뮬레이션
- 정책 설정 후 결과를 즉시 시각화
- 예: 연차 자동 부여 미리보기 테이블, 자동 근무 기록 그래픽

### 13) Empty State 디자인
- "+ 추가하기" 또는 "비어 있어요" 메시지
- 모든 빈 리스트에 일관 적용

### 14) 점프 칩
- 긴 폼의 섹션 네비게이션 ("다음으로 이동..." 칩 그룹)
- 사이드 패널 하단에 배치

### 15) 양방향 뷰 (디버깅용)
- 권한 그룹 ↔ 구성원 권한 (서로 점프 가능)
- "왜 이 사람이 이걸 볼 수 있지?"를 추적

### 16) 락아웃 방지 안전장치
- IP 화이트리스트 저장 시 "현재 접속 IP 추가" 버튼
- 빈 화이트리스트 저장 차단
- 최고 관리자 IP 제외 토글 기본 OFF

## 14. 구성원 상세 페이지 마무리 (P1 영역)

### 14-1. 휴직 등록 모달 ⭐
**필드**:
- 휴직 종류* (육아/병가/개인사유 등 마스터)
- 휴직 기간* (시작~종료)
- **근속기간 포함*** (포함/미포함 토글) ⭐ — 연차/퇴직금 계산 영향
- **급여지급률*** (%, 기본급 기준) ⭐ — 단순 paid/unpaid 아님, 비율
- 메모 (🔒 인사 권한자만)

→ 결재선 진입점 없음 (인사 권한자 직접 등록)

### 14-2. 수상 / 교육 — "사내/외부" 칩 패턴 공통
- 수상: 사내 수상 / 외부 수상 칩 + 기관명
- 교육: 사내 교육 / 외부 교육 칩 + 기관명
- → 공통 컴포넌트 후보

### 14-3. 징계 추가
- 일자가 **기간**으로 받음 (감봉 6개월 같은 적용 기간)
- 종류 enum (경고/감봉/정직/...)

### 14-4. 경력 / 학력 모달
- 경력: 회사명 / **계약유형** (`EmploymentType` 재사용) / 입퇴사 년월(일 단위 아님) / 직무·조직·직위(자유 텍스트, 마스터 매핑 X)
- 학력: 학교 구분 (고졸/대졸/석사/박사) + 학교명 분리 / 졸업 구분 (졸업/수료/중퇴/재학)

### 14-5. 특이사항 ⭐⭐ 큰 발견
**Flex의 "특이사항" = 세제/근태 특수 처리 플래그 4종** (자유 텍스트 아님)
- 육아기 단축 근무 (기간)
- 외국인 단일 세율 (기간)
- 소득세 감면 (감면 종류)
- 학자금 대출 상환 (기간)

→ 데이터 모델 수정 필요: `SpecialNote` (자유 텍스트) → `EmployeeTaxSpecialStatus` (구조화 4컬럼)

### 14-6. 가족 정보 ⭐⭐ 매우 풍부
**3섹션 구조**:
1. **기본 정보**: 이름 / 관계 / 휴대전화번호
2. **공제 정보**:
   - 주민등록번호 (외국인등록번호)
   - 소득 공제 관계 + "기본공제대상" 토글
   - 장애인·국가유공자 (드롭다운)
   - ☐ 건강보험 피부양자 + "피부양자 기준 알아보기" 링크
3. **증명 서류** (모달에 인라인 통합!):
   - + 가족관계증명서
   - + 주민등록등본
   - + 장애인증명서 (장애인 선택 시 활성)
   - + 국가유공자증명서 (선택 시 활성)

**가족 정보 섹션 헤더**: `총 공제 대상 (기본 공제 N명, 건강보험 피부양자 N명)` — 자동 집계

### 14-7. 성장 탭 (본인 작성)
- 빈 상태: "나의 성장을 기록해보세요" + [성장 기록하기] 버튼
- 본인이 자유 작성하는 성장 일지 (타임라인)
- → 우리 스코프: **P2 보류** (Phase 4 평가 영역)

### 14-8. 교육 탭
**교육 추가 모달**:
- 교육 이름* / 교육 일자* / 유형 (온라인/오프라인 칩)
- 교육 기관: 사내/외부 칩 + 기관명
- 교육 구분 (직무/리더십/법정의무 등)
- 총 교육 시간 + 단위 선택 (시간/일)

→ 법정 의무 교육(성희롱예방, 개인정보보호) 관리 가능. P1.

### 14-9. 문서·증명서 탭 (2-column)
**좌측 — 내 문서** (직원이 제출하는 서류 슬롯)
- 가족관계증명서, 건강보험득실확인서, 이력서, 신분증사본, 급여계좌사본, 학력증명서, 주민등록등본
- 각 슬롯 hover 시 연필 아이콘 (인라인 업로드)
- **하단**: "가족 문서" 섹션 — 가족 정보 모달의 첨부와 데이터 동기화

**우측 — 증명서 발급** (회사 → 직원)
- 재직증명서 / 경력증명서 [발급 받기]

→ 직원 제출 슬롯 = `DocumentSlot` + `EmployeeDocument` (설정 메뉴와 연동)
→ 증명서 발급 = P2

### 14-10. 인사노트 탭 (P1)
- 채팅/타임라인 UI
- 입력창: "메모할 구성원 정보가 있나요?" (인라인 작성)
- 본인이 자기 페이지에서도 작성 가능해 보이나, 실제론 인사 권한자가 작성
- 공개 범위 설정 (HR / 매니저 / 본인)
- 짧은 메모 누적 (긴 텍스트 X)

## 15. 글로벌 UI — 알림

### 빈 상태 (Empty State)

## 16. 글로벌 UI — 검색 ⭐⭐ 큰 발견

### 정체: 검색이 아니라 **커맨드 팔레트(Command Palette)**
Notion/Linear/VS Code의 `Cmd+K` 패턴. 검색 + 빠른 액션 + 컨텍스트 점프 허브.

### 메인 구조
- 상단: ⚡ 검색어 입력 (번개 아이콘)
- **빠른 액션 5개**:
  1. ➕ 할 일 요청 → 워크플로우 작성 진입
  2. 👤🔍 구성원 검색
  3. 📄🔍 워크플로우 검색
  4. 📄 워크플로우 작성 (양식 선택 후 작성)
  5. ⏱ 근무 기록 확인 ← ❌ 우리 스코프 외 (근태 제외)

### 모드 진입 패턴
- 모드 선택 시 좌측 상단 **모드 칩** 표시 + 검색창에 컨텍스트 힌트
- 워크플로우 작성: 카테고리 칩 필터 (전체/구매신청/복리후생/비용처리/계약/업무신청) + 양식 리스트

### 핵심 발견
- "검색"이 아니라 **"허브"** — 모드 = 검색 범위 사전 분류
- 권한 scope 문제 자연 해결 (모드별로 scope 다르게 적용)
- 검색이면서 동시에 액션 트리거
- Flex는 ⌘K 단축키 없어 보임 → 우리 차별화 포인트

### 우리 결정 (확정)
- **메뉴명 = "검색"** (단축키는 숨김)
- **⌘K / Ctrl+K** 단축키 P0 (UI에 작은 hint 칩)
- **검색 인프라**: PostgreSQL `pg_trgm` + 한국어 형태소 분석 (Mecab/노리)
- **AI 자연어 명령 P0** — 모드 없이 자연어 입력 → 의도 분류 → 자동 진입

## 17. 글로벌 UI — 동료에게 전달하기

### 메인 허브 — 5개 액션
1. 🧷 **공지사항 작성하기** (코랄) — 공지사항 게시
2. ✅ **할 일 요청하기** (초록) — 구성원에게 할 일
3. ✏️ **작성 요청하기** (청록) — 구성원에게 문서 작성 요청
4. 💜 **인정 메시지 보내기** (보라) — 인정·응원
5. ✉️ **피드백 메시지 보내기** (회색) — 애정어린 피드백

### ⭐⭐ 핵심 발견 — 5개 아니라 3+2 묶음

**그룹 A: 워크플로우 트랙** (FormDocument 생성)
- 공지사항 / 할 일 요청 / 작성 요청
- UI 거의 동일, 좌측 상단 칩만 다름 (드롭다운으로 모드 전환 가능)
- 작성 요청만 "작성할 문서 찾아보기" 셀렉터 하나 더

**그룹 B: 메시지 트랙** (별도 테이블)
- 인정 / 피드백 — UI 거의 동일, 칩과 드롭다운 옵션만 다름

### 받는 사람 선택 UX (RecipientPicker 공통 컴포넌트)
- 검색 + "조직도 보기" 토글
- "전체 구성원" 옵션 (전사 발송)
- 조직 목록 / 구성원 목록
- ☑️ "하위 조직 함께 선택"
- 좌측: 후보 / 우측: 선택됨 (다중)

→ **결재선 선택 컴포넌트와 동일** — 4곳에서 재사용 (결재/참조/정보변경/전달)

### 마감일 픽커
빠른 칩: 오늘까지 / 내일까지 / 3일 뒤까지 / 다음 주까지 + "직접입력" 토글

### 인정 메시지 5종 (시스템 시드)
- ✌🏻 진짜 멋져요! / 🥳 최고예요! / 🤩 엄청 놀라워요! / 🙏🏻 정말 고마워요! / 💖 감동이에요!

### 피드백 주제 4종 (시스템 시드)
- 커뮤니케이션 / 업무 스킬 / 회사 문화 / 핵심 가치

### 우리 결정
- **인정/피드백 P1** (자리만)
- **피드백 = sender↔recipient 1:1 비공개** (HR도 못 봄, 심리적 안전)
- **인정 종류/피드백 주제 회사별 커스터마이즈** (시스템 시드 + 회사 추가)

## 18. 회사 페이지 + 가입/등록 흐름 ⭐ 보너스 발견

### 회사 페이지 (좌측 상단 로고 클릭)
**진입 드롭다운**:
- 회사 정보 / 내 설정 / 넓게 보기 토글
- **회사 목록** ← 멀티 테넌시 신호
- 로그아웃

**페이지 구조**:
- 헤더: 큰 로고 + 커버 + 회사명 + 칩 `대표 이름` `구성원 N명` `📋 회사코드`
- 4탭: 회사 문서 / 근무 정책(❌) / 휴가 정책 / 쉬는 날
- 우측 사이드: VISION & MISSION + 설립일 + **설립 N일째 라이브 카운터** ⭐ + 사업자/법인번호/연락처/주소

### 발견
- **회사코드** = 외부 직원 초대용 ID
- **회사 페이지가 회사 정체성 랜딩** — 신입사원 온보딩
- 회사 문서/휴가 정책이 두 곳에 노출 (관리 메뉴 + 회사 페이지) — 같은 데이터 다른 진입점
- **설립 N일째 카운터** — 정서적 차별화 포인트 (채택)

### 우리 가입/등록 흐름 (확정 설계)

**Flow 1: 회사 생성 (Sales-led, B2B SaaS 표준)**
```
잠재 고객 → "회사 등록 신청" 폼 (회원가입 + 회사 정보)
시스템 관리자 → 검토 → 승인/반려
승인 시 → Company 생성 + 회사코드 발급 + 신청자 = 회사 대표 권한
회사 대표 → 초기 셋업 마법사 (정보 보강 → 조직도 → 직위/직책 → 휴가 정책 → 권한 검토)
```

**Flow 2: 직원 가입 (회사코드 + HR 승인)**
```
직원 → 회원가입 + 회사코드 입력 → 가입 신청 (pending_approval)
HR → 가입 요청 검토 → 승인/반려
승인 시 → Employee 생성 + 발령(Appointment) 모달
```

**Flow 3: HR이 직원 초대 (역방향)**
```
HR → "+ 직원 초대" → 이메일 또는 CSV 일괄
직원 → 초대 메일 링크 → 비번 설정 → 즉시 활성화
```

### 액터 분리
- 시스템 관리자 (B2B 세일즈)
- 회사 대표 / HR 관리자
- 일반 직원
