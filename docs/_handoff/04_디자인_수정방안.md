# 04. 디자인 수정방안 (핸드오프)

> **목적**: Teamlet(국내 HR SaaS, Flex 대체)의 디자인·기능을 "Claude 디자인"으로 재정립·업그레이드하기 위한 실행 핸드오프.
> **원천**: `docs/_transcribe/flex.md`(Flex 347장 전수 전사) + `docs/_transcribe/flexv2.md`(휴가 97장 심층) + 현행 `apps/web/src/app/design.css` / `packages/ui/src/theme/tokens.css` / `docs/05_디자인_시스템.md`.
> **불변 제약(CLAUDE.md 5원칙 / Anti-Pattern)**: ① 초록→청록 그라데이션 절대 금지(Primary=Slate 900 단색, Accent=Cool Blue 600) ② 큰 컬러풀 아이콘 카드(Flex 시그니처) 금지, 아이콘=Lucide ③ 패턴 차용 OK·시각/텍스트는 우리 것으로 변주 ④ 토큰만 사용(임의 hex 금지) ⑤ `success-500(#22c55e)`은 의미적 success에만, 메인/브랜드 컬러 금지.
> **추정 표기**: 화질 한계로 확정 못한 항목은 본문에서 "추정:"으로 표기.

## 1. 요약

### 현재 상태 (한 문단)
Teamlet의 디자인 토큰(`packages/ui/src/theme/tokens.css`)과 브리지 CSS(`apps/web/src/app/design.css`)는 이미 Cool Slate 팔레트로 잘 정립되어 있고, 그라데이션·초록 메인 사용은 토큰 레벨에서 차단되어 있다(원칙 준수). 그러나 (a) 11개 핵심 패턴 컴포넌트 중 `packages/ui/src/patterns/`에 실제 구현된 것은 **AppliedDateChip / DirtyGuardModal / EmptyState 3개뿐**이고, RecipientPicker·CommandPalette는 `apps/web/src/components/`에 흩어져 있어 "4곳 재사용·단일 소스" 원칙이 코드로 강제되지 않는다. (b) 도메인 페이지(`home/members/leave/workflow/recruit/documents/settings/*`)는 대부분 스캐폴드 상태로, Flex가 제공하는 **정책 문구·선택창 옵션·이벤트→모달 분기**의 풀스펙 깊이를 아직 못 따라간다. (c) design.css에 `--purple/#7c3aed`·`--purple-50/#faf5ff` 같은 **하드코딩 hex**와, `.av`·`.profile-av`의 `linear-gradient(...)`가 남아 있어 원칙 4·5를 국소 위반한다.

### 재정립 방향 (3–5줄)
1. **토큰 위반 잔재 제거** — design.css의 하드코딩 `purple` hex와 아바타 `linear-gradient`를 토큰/단색으로 치환. (P1, 30분 작업)
2. **공통 컴포넌트를 `packages/ui/patterns/`로 승격·단일화** — RecipientPicker(1~5차 조직장 동적역할 포함)/CommandPalette/ApprovalLineDrawer/시점 피커/마스터 CRUD 모달을 패턴화해 재사용 강제(Anti-Pattern #10 코드화).
3. **Flex 패턴 → Slate 변주 매핑을 화면별로 적용** — 발신 허브·연차정책 빌더·결재선 빌더·연차 원장·촉진 플로우의 verbatim 문구/선택창 옵션/이벤트 분기를 그대로 기능에 이식하되 시각은 Cool Slate로.
4. **법적 안내문은 의미만 차용** — 회계연도 부여 경고/소수점 수당 의무/촉진 면책 문구를 Teamlet 톤으로 재작성(직접 카피 금지).

## 3. 도메인별 갭 & 수정방안

각 도메인: **(a) Flex 핵심 화면·이벤트·선택창(전사 인용)** → **(b) 현재 Teamlet** → **(c) 수정방안**.

### 3.1 홈 (홈 피드 / 회사 소식 / 할 일)

**(a) Flex** — 3단 레이아웃(GNB·피드·우측 위젯). 메인 탭 `"홈 피드" · "회사 소식" · "할 일"`. 우상단 발신 허브 CTA `"동료에게 전달하기"` → **5종 액션 메뉴**([172136], 부제 `"아래에서 전달하기 원하는 내용을 선택해 주세요."`):
- `"공지사항 작성하기"` → 공지 모달([171611]): 제목 placeholder `"공지사항 제목"`, `"받는사람 선택"`, 본문 `"동료에게 보낼 공지사항 내용을 작성해 주세요."`, 첨부 `"이미지, PDF, Zip 등을 첨부할 수 있어요."`
- `"할 일 요청하기"` → 종류 선택 팝오버([171922]): `"할 일 요청"` / `"문서 작성 요청"`. 작성 폼은 좌(본문)·우(`"요청 대상 구성원"` `"아래 선택된 구성원들에게 개별적으로 할 일을 요청하게 돼요"`) 2-pane. 마감일 프리셋([172008]): `"오늘까지/내일까지/3일 뒤까지/다음 주까지/직접입력"`(보조에 실제 날짜 병기).
- `"작성 요청하기"`(문서) · `"인정 메시지 보내기"`(프리셋 [172158] 👏`"진짜 멋져요!"`/🙌`"최고예요!"`/😮`"엄청 놀라워요!"`/🙏`"정말 고마워요!"`/🥹`"감동이에요!"`, 본문 `"...메시지를 작성해 주세요. (필수)"`) · `"피드백 메시지 보내기"`(주제 [172234]: `"커뮤니케이션/업무 스킬/회사 문화/핵심 가치"`).
- 빈상태: 공지 `"공지사항을 작성해볼까요?"` / `"우리 회사 구성원들에게 알려주고 싶은 내용을 공지사항으로 작성해보세요!"` + `"작성하기"`. 인정 `"아직 동료에게 전달한 인정이 없어요."`. 할일 `"요청받은 일이 없어요."` / `"동료가 나에게 요청한 모든 일이 이곳에 쌓입니다."`.
- 우측 위젯: 캘린더(`"일정이 없어요."` + `"일정 보기"`), 일정 위젯 모달([172304]) 좌측 필터 `"일정 구분"`(근무/휴가/채용 인터뷰/기념일 체크), 보기 옵션([172318]) `"주말 포함해서 보기"` / `"확정 일정만 보기"`(=미확정 휴가 숨김).
- **이벤트로 뭐가 열리나**: 발신 허브 5분기 → 각 작성 모달. 모든 작성 모달의 `"받는사람 선택"` → **동일 RecipientPicker**. 작성 중 닫기 → 이탈 다이얼로그([172103]) `"작성을 그만할까요?"` / `"지금 할 일 작성을 종료하면, 작성한 내용은 저장되지 않고 삭제됩니다."` / `"그만하기"`(파괴)·`"아니요"`.

**(b) 현재 Teamlet** — `(app)/home/page.tsx` 존재. design.css에 `.event-row`/`.post`/`.todo-row`/`.widget`/`.cal` 등 홈 클래스 풀세트 보유(이미 3단 레이아웃·이벤트카드·공지카드·할일·미니캘린더 스타일 완비). 발신 허브 5종 메뉴·인정/피드백 모달은 추정: 미구현.

**(c) 수정방안**
1. **발신 허브를 모노톤 행 리스트로** — Flex 5색 카드 금지. `.auth-option` 패턴(아이콘 좌·제목/보조설명) 차용: `Megaphone/CheckSquare/FileText/Heart/MessageSquare`(Lucide, `text-foreground-muted`). 부제 우리 톤으로 재작성("무엇을 전달할까요?").
2. **인정/피드백 = 정형 프리셋 드롭다운 + 자유입력(필수)** 그대로 이식하되 이모지는 데이터 본문에만(원칙 #12 허용). 피드백 주제 4축은 향후 인사이트(People Analytics) 데이터로 누적.
3. **할 일 = 워크플로우 통합** — 별도 엔진 만들지 말 것. `FormDocument.document_kind`로 공지/할일/문서요청 통합(전사 [171844] "요청한 일"에 휴가 승인 요청 섞임이 통합 입증).
4. **일정 위젯 "확정 일정만 보기"** = 결재 전(미확정)/후(확정) 휴가를 캘린더 색/배지로 구분. 미확정=`--primary-soft` 점선, 확정=실선.
5. **이탈 다이얼로그는 `DirtyGuardModal` 강제**(이미 패턴 존재). 문구 표준화는 §4-5 참조.

### 3.2 구성원 (목록 / 초대 / 벌크 / 프로필)

**(a) Flex**

### 4-1. RecipientPicker (★★ 4곳 재사용, Anti-Pattern #10)

- **모드**: 결재 단계(승인 ✓) / 참조(🔔 알림 3옵션: 요청·완료/완료만/없음) 구분.
- **Teamlet 변주**(docs/05 §4-2): 권한 scope 시각화(볼 수 없는 사람=회색+자물쇠), 최근 선택 5명 빠른칩, 한국어 형태소 매칭(`김유`→`김유민`). 조직 루트 = `companyId` 스코프.

### P2 — Core HR + 휴가 풀스펙 (핵심 도메인)
