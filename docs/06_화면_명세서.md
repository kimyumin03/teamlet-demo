# 화면 명세서

> HR SaaS 화면 정의 — 라우트별 데이터 의존성/액션/권한 매핑
> **최종 업데이트**: 2026.5.19
> 5가지 원칙 준수. Phase 1~4 (P0) 화면 명세 + P1~P2 자리 표시.

---

## 📐 명세 포맷 (모든 화면 공통)

각 화면마다 다음 정보를 명세:

```
### 화면명
- 경로 (Route): /...
- 권한 (Permission): 필요한 권한 키
- 데이터 (Data): 어떤 테이블·쿼리에 의존하는지
- 컴포넌트 (Components): 어떤 핵심 컴포넌트를 쓰는지
- 액션 (Actions): 사용자가 할 수 있는 행동
- 비즈니스 룰 (Rules): 도메인 제약사항
- 빈 상태 (Empty): 데이터 없을 때 노출 방식
```

# 🟢 PHASE 1 — Foundation (인증 / 가입 / 권한)

이 단계 화면들이 가장 먼저 만들어져야 함. **회사·사용자 셋업이 안 되면 다른 모든 화면이 의미 없음.**

## 1.1 로그인

### `/login`

- **경로**: `/(auth)/login`
- **권한**: 비로그인만 접근. 로그인 상태에서는 `/home`으로 리다이렉트.
- **데이터**: 없음 (Auth.js credential check)
- **컴포넌트**: 기본 Form (Input + Button) + Logo
- **액션**:
  - 이메일/비밀번호 로그인
  - "비밀번호 찾기" 링크 → `/forgot-password`
  - "회원가입" 링크 → `/signup`
  - "AxHub 계정으로 로그인" 버튼 (옵션, `AXHUB_ENABLED=true`일 때만)
- **비즈니스 룰**:
  - 로그인 실패 N회 시 잠금 (`CompanyLoginPolicy.max_login_attempts`)
  - 2FA 활성화 사용자 → `/login/2fa` 단계 추가
  - 회사 IP 화이트리스트 적용 시 외부 IP 차단 또는 2FA 강제
  - 휴직자 로그인 허용 토글 (`CompanyLoginPolicy.allow_leave_of_absence_login`)
- **빈 상태**: N/A

### `/login/2fa`

- **경로**: `/(auth)/login/2fa`
- **권한**: 1차 인증 완료 세션만 접근
- **데이터**: `UserMFA` (TOTP 비밀키)
- **컴포넌트**: 6자리 OTP 입력 (자동 포커스 이동)
- **액션**: OTP 검증 / 백업 코드 사용
- **비즈니스 룰**:
  - 회사 2FA 강제 정책 시 무조건 요구
  - 사무실 IP (`mfa_exempt_ips`)에서는 자동 건너뜀

## 1.2 회원가입 + 회사 가입 흐름

### `/signup`

- **경로**: `/(auth)/signup`
- **권한**: 비로그인만
- **데이터**: 없음 (신규 User 생성)
- **컴포넌트**: 다단계 폼 (Stepper)
- **액션**: 이름 / 이메일 / 비밀번호 / 휴대폰 입력 → User 생성 → 이메일 인증 메일 발송 → `/join-company` 이동
- **비즈니스 룰**:
  - 비밀번호 정책 검증 (`CompanyLoginPolicy.password_policy`)
  - 이메일 중복 차단
  - reCAPTCHA 또는 hCaptcha (스팸 방지)
- **빈 상태**: N/A

### `/join-company`

- **경로**: `/(auth)/join-company`
- **권한**: 로그인 + 활성 회사 멤버십 없는 상태
- **데이터**: `Company`, `JoinRequest`, `EmployeeInvite`
- **컴포넌트**: 3가지 진입 옵션 선택 카드
- **액션**:
  1. **회사 등록 신청** → `/register-company` (CompanyApplication 생성)
  2. **회사코드로 가입** → 코드 입력 → JoinRequest 생성 → "승인 대기" 상태
  3. **초대 메일 받은 경우** → 메일 링크 클릭 시 토큰으로 자동 매칭 → 즉시 활성화
- **비즈니스 룰**:
  - 회사코드 유효성 검증 (`Company.company_code_active`)
  - 같은 회사에 중복 신청 차단
- **빈 상태**: "어떤 회사에 가입하시겠어요?" 안내

### `/register-company`

- **경로**: `/(auth)/register-company`
- **권한**: 로그인 + 회사 등록 신청 없는 상태
- **데이터**: `CompanyApplication`
- **컴포넌트**: 다단계 폼
- **액션**: 회사명 / 사업자번호 / 대표자 / 연락처 / 규모 / 업종 / 메모 → 신청 → "검토 대기" 상태
- **비즈니스 룰**:
  - 사업자번호 형식 검증 (XXX-XX-XXXXX)
  - 중복 사업자번호 차단
  - 자동 알림 발송 (시스템 관리자에게)
- **빈 상태**: N/A

### `/pending-approval`

- **경로**: `/(auth)/pending-approval`
- **권한**: 로그인 + `JoinRequest.status = pending` 또는 `CompanyApplication.status = pending`
- **데이터**: 본인의 대기 신청
- **컴포넌트**: 안내 화면
- **액션**: 신청 취소 / 로그아웃
- **빈 상태**: N/A

## 1.3 시스템 관리자 — 회사 등록 검토

### `/admin/company-applications`

- **경로**: `/(admin)/company-applications`
- **권한**: 시스템 관리자만 (`SYSTEM_ADMIN_EMAILS` 환경변수)

  ```sql

  ORDER BY 신청일 DESC
  ```

- **액션**:

  - 반려 → 사유 입력 + 메일 발송
- **비즈니스 룰**: 회사코드는 XXXX-XXXX 형식 자동 생성 (충돌 시 재시도)
- **빈 상태**: `EmptyState` ("검토할 신청이 없어요")

## 1.5 HR — 직원 가입 요청 검토

### `/(app)/settings/join-requests`

- **경로**: `/(app)/settings/join-requests`
- **권한**: `member.management` 권한 (HR 권한자)
- **데이터**:
  ```sql
  SELECT * FROM join_requests
  WHERE company_id = $1 AND status = 'pending'
  ORDER BY 신청일 DESC
  ```
- **컴포넌트**: 테이블 + 승인 모달
- **액션**:

  - 반려 → 사유 + 메일 발송
- **비즈니스 룰**: 승인 시 즉시 발령 정보(조직/직위/입사일) 입력 필수
- **빈 상태**: "대기 중인 가입 요청이 없어요"

# 🟢 PHASE 2 — Core HR

## 2.1 홈 피드

### `/home`

- **경로**: `/(app)/home`
- **권한**: 모든 로그인 사용자
- **데이터**:
  - `FormDocument` (내가 결재할 것 / 신청한 것 / 참조)
  - `Notification` (최근 알림)
  - `CompanyHoliday` (이번 달 쉬는 날)
  - `LeaveBalance` (내 휴가 잔여)
  - 본인 `Employee` (프로필 카드)
- **컴포넌트**: 3-column 레이아웃 + 탭 (홈 피드 / 회사 소식 / 할 일)
- **액션**:
  - 결재 클릭 → 해당 `FormDocument` 상세
  - 할 일 클릭 → 작업 진입
  - "동료에게 전달하기" 버튼 → 액션 허브 모달
- **비즈니스 룰**:
  - "할 일" = `FormDocument.document_kind in ('task_request','doc_request')` + 본인이 담당자
  - 권한 scope 적용 (참조자 권한 없는 문서는 제외)
- **빈 상태**: 각 섹션별 `EmptyState`

### "동료에게 전달하기" 액션 허브 모달

- **트리거**: 헤더 또는 홈 페이지 버튼
- **데이터**: `FormTemplate` (시스템 시드 3개) + `RecognitionType`/`FeedbackTopic`
- **컴포넌트**: 5개 액션 카드 모달
- **액션**: 5개 진입점
  1. 공지사항 작성 → `FormDocument(kind=announcement)` 작성 화면
  2. 할 일 요청 → `FormDocument(kind=task_request)` 작성 화면
  3. 작성 요청 → `FormDocument(kind=doc_request)` 작성 화면 (양식 선택 포함)
  4. 인정 메시지 (P1) → `RecognitionMessage` 작성
  5. 피드백 메시지 (P1) → `FeedbackMessage` 작성

## 2.2 구성원

### `/members`

- **경로**: `/(app)/members`
- **권한**: `member.read` (scope 적용)
- **데이터**:
  ```sql
  SELECT e.*, ph.* FROM employees e
  LEFT JOIN position_history ph ON ph.employee_id = e.id
    AND ph.effective_date <= $기준일
    AND (ph.next_effective IS NULL OR ph.next_effective > $기준일)
  WHERE e.company_id = $1
    AND e.id IN ($권한_scope_employee_ids)
  ```
- **컴포넌트**: 탭 (전체 / 입사 / 퇴사 / 초대 현황) + 테이블 + 기준일 필터
- **액션**:
  - **"+ 구성원 초대"** → 초대 모달 (이메일 단건 또는 작은 수 추가)
  - **"+ 일괄 가져오기"** ⭐ → `/members/bulk-import` 진입 (CSV 업로드)
    - 권한: `member.bulk_import`
    - MVP에서는 CSV만, AxHub 연동 후 "AxHub에서 동기화" 옵션 추가
  - **"내보내기"** → `member.bulk_export` 권한자만
    - 현재 필터/기준일에 맞는 직원 CSV 다운로드
  - 행 클릭 → 구성원 상세 (`/members/[id]`)
  - 검색 / 필터 / 정렬
  - **기준일 변경** ⭐ — 과거 시점 조회
- **비즈니스 룰**:
  - 기준일 = 오늘 기본
  - 권한 scope에 따라 보이는 직원 다름 (`scope_type` 적용)
  - AxHub 동기화로 들어온 직원은 행에 작은 AxHub 배지 표시
- **빈 상태**:
  - 직원 0명 (신규 회사): "+ 구성원 초대" 또는 "+ 일괄 가져오기" 두 버튼 강조

### `/members/org-chart`

- **경로**: `/(app)/members/org-chart`
- **권한**: `member.read`
- **데이터**: `Department` 계층 + `PositionHistory` (현재 또는 기준일)
- **컴포넌트**: 트리 시각화 (react-org-chart 또는 d3-hierarchy)
- **액션**:
  - 부서 클릭 → 부서 상세 (구성원 리스트)
  - 직원 클릭 → 구성원 상세
  - 기준일 변경
- **빈 상태**: "조직도가 비어있어요" + 부서 추가 안내

### `/members/[id]` — 구성원 상세 페이지 ⭐⭐ 가장 큰 화면

- **경로**: `/(app)/members/[id]`
- **권한**:
  - `member.personal_info.read` (기본 정보)
  - `member.hr_info.read` (인사 정보)
  - 본인은 항상 자신의 페이지 접근 가능
  - 일부 섹션은 권한별 마스킹 (`SensitiveLock`)
- **데이터** (가장 복잡):
  - `Employee` (기본)
  - `PositionHistory` (현재 시점)
  - `EmploymentContractHistory`, `SalaryContractHistory`
  - `WorkTypeAssignmentHistory`, `LeavePolicyAssignment`, `CalendarAssignment`
  - `LeaveOfAbsence`, `Award`, `Discipline`, `CareerHistory`, `EducationHistory`
  - `EmployeeTaxSpecialStatus`, `FamilyMember`, `FamilyMemberDocument`
  - `LeaveBalance`, `EmployeeDocument`
- **컴포넌트**:
  - 헤더 (커버 + 아바타 + 이름 + 칩)
  - 5개 상단 탭 (정보 / 성장(P2) / 교육(P1) / 문서·증명서 / 인사노트(P1))
  - 정보 탭: 16개 섹션 + 우측 `JumpChips`
  - 우측 상단 ⏱ **"정보 변경 내역"** 버튼
- **액션**:
  - 각 섹션 "+ 추가" 또는 "✏ 변경" → 모달 진입
  - 모든 변경 모달은 `AppliedDateChip` + `ApprovalLineDrawer` 패턴
  - `RetroactiveWarning` 표시 (휴가 정책 / 쉬는 날 변경 시)
  - `SensitiveLock` 적용 (급여 / 임금 계약 등 민감 정보)
- **비즈니스 룰**:
  - 모든 변경은 `Appointment` 트랜잭션 생성
  - 시점 기반 = `PositionHistory` 새 row 추가, UPDATE 금지
  - 본인 정보 변경은 워크플로우 거침 (`member_info_change` 카테고리)
- **빈 상태**: 각 섹션별 "+추가" 인라인 버튼

### `/members/[id]/history` — 정보 변경 내역

- **경로**: `/(app)/members/[id]/history`
- **권한**: `member.hr_info.read`
- **데이터**: 도메인별 이력 테이블 6개
- **컴포넌트**: 6개 탭 (인사 / 근로 계약 / 임금 계약 / 급여 지급(스코프외) / 근무 / 초과 근무 보상(스코프외))
- **액션**:
  - 시점별 이력 조회
  - "+ 내역 추가하기" → 발령 모달
- **빈 상태**: "변경 내역이 없어요"

## 2.3 구성원 벌크 임포트 ⭐ (CSV·AxHub 공통 인프라)

### `/members/bulk-import` — 업로드 단계

- **경로**: `/(app)/members/bulk-import`
- **권한**: `member.bulk_import`
- **데이터**: `BulkOperation` (진행 중인 작업 있으면 표시)
- **컴포넌트**:
  - 파일 업로드 영역 (드래그앤드롭 + 클릭 업로드)
  - "CSV 템플릿 다운로드" 버튼 (필수/선택 컬럼 명시된 빈 CSV)
  - 안내 문구 (필수 컬럼, 인코딩=UTF-8, 행 제한 등)
  - **AxHub 연동 활성화 시**: "AxHub에서 동기화" 옵션 카드 추가 (P2)
- **액션**:
  - CSV 업로드 → S3 저장 → `BulkOperation(csv_import_employees)` 생성 (`status=queued`)
  - 백그라운드 잡(BullMQ)이 파싱·검증 시작
  - 진행 상태 페이지로 자동 이동 (`/members/bulk-import/[operationId]`)
- **비즈니스 룰**:
  - 동시 진행 작업 1개 제한 (한 회사당) — 충돌 방지
  - 파일 크기 제한 (예: 10MB)
  - 진행 중인 작업 있으면 신규 업로드 차단 + 기존 작업으로 안내
- **빈 상태**: 안내 + 템플릿 다운로드 강조

### `/members/bulk-import/[operationId]` — 진행·검토·확정

- **경로**: `/(app)/members/bulk-import/[operationId]`
- **권한**: `member.bulk_import` + 본인이 시작한 작업이거나 HR 관리자
- **데이터**: `BulkOperation`, `BulkOperationRow[]`
- **컴포넌트**: 상태별 분기 화면
  - **`validating`** — 진행률 + "검증 중" 안내 (페이지 자동 새로고침 또는 SSE)
  - **`awaiting_confirm`** — 검토 화면 ⭐ (가장 중요):
    - 상단 요약 카드: 전체 N건 / 유효 N / 충돌 N / 에러 N
    - 탭: 전체 / 유효 / 충돌 / 에러
    - 행별 미리보기 (원본 + 검증 결과 + 충돌 시 해결 옵션 드롭다운)
    - **충돌 해결 옵션 칩**: 스킵 / 덮어쓰기 / 새로 생성 (행마다 또는 일괄)
    - 하단 **"확정 적용"** 버튼 (Primary, slate-900) + "취소" 버튼 (transparent)
    - `DirtyGuardModal` 적용 (검토 변경 중 이탈 시도 차단)
  - **`running`** — 실시간 진행률 + 라인별 처리 결과 (성공/실패 카운트)
  - **`completed`** — 결과 요약 + "롤백" 버튼 (24h 내) + "엑셀 다운로드" (실패 행 별도)
  - **`failed`** — 에러 사유 + "다시 시도" + "취소"
- **액션**:
  - 충돌 해결 옵션 선택 (행별 또는 일괄)
  - **확정 적용** → 백그라운드 잡 실행 → `BulkOperationRow` 라인별 처리 → `Appointment` 자동 생성 → `Employee` 생성/업데이트
  - **롤백** → 24h 내, 생성된 row 모두 `deleted_at` 표시 + 업데이트된 필드 이전 값 복원
  - **실패 행 재시도** → 실패 행만으로 신규 `BulkOperation` 생성
- **비즈니스 룰**:
  - 확정 시 모든 변경은 단일 트랜잭션 (`Appointment` 1개로 묶음, `appointment.label = 'CSV 일괄 등록'`)
  - 시점 기반 이력 보장 — `PositionHistory` 새 row 생성 (UPDATE 금지)
  - 모든 변경 → `AuditLog` 기록 (`operation_type = bulk_import`)
  - 확정자(`confirmed_by_user_id`)는 모든 라인의 `Appointment.created_by`로 기록
- **빈 상태**: N/A (operationId 없으면 404)
