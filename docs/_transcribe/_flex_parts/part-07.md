# flex 전사 — part 07 (batch-07, 24장)

> 도메인: **워크플로우(전자결재) / 내 문서함·회사 문서함 / 문서 양식(템플릿) 관리·생성**
> URL 흐름: `flex.team/workflow/archive/my/?tab=in-progress` → `tab=done` → `tab=star` → `tab=all` → `flex.team/workflow/archive/all/?tab=...`(회사 문서함) → 문서 양식 관리 드로어 → 양식 만들기 모달
> 핵심 발견: 워크플로우는 결재 "문서함"(내/회사)과 "양식(폼 템플릿) 관리"가 한 화면에서 분기. 양식 = `FormDocument` 템플릿 + 승인선(참조/N단계 승인) 정의. 양식 분류는 7개 카테고리(구매신청/휴가/복리후생/비용처리/계약/업무신청/전체).

## 공통 레이아웃 (전 화면 공통)

- **좌측 GNB (고정, 세로)** — 회사 스위처 상단(`주식회사 대모산개발단`, 하단에 `근무중 · 자동 기록 중 ▾` 상태 셀렉터). 그 아래 메뉴 순서:
  - `내 프로필`
  - `검색` (단축키 칩 `Ctrl K`)
  - `알림`
  - 구분선
  - `홈 피드`
  - `구성원`
  - `근무`
  - `휴가`
  - `근태 관리`
  - `워크플로우` ← 현재 활성(연한 회색 배경 하이라이트)
  - `후보자 평가`
  - `채용`
  - `인사이트`
  - `문서·증명서`
  - `설정`
  - `추가 기능 ▾`
  - `단체 보험` (최하단, 흐릿/접힘)
- **상단 영역**: 페이지 타이틀 영역에 `내 문서함`(굵게/활성) + `회사 문서함`(회색/비활성) 두 개의 큰 토글 타이틀이 나란히. 우측 상단에 흰색 보조 버튼 `📄 문서 양식 관리`, 초록 그라데이션 CTA `✏️ 문서 작성하기`.
- **탭 바**(타이틀 하단): 내 문서함 = `진행중 / 완료 / 중요 / 전체`. 회사 문서함 = `진행중 / 완료 / 전체` (중요 탭 없음). 활성 탭은 검정 굵게 + 하단 밑줄.
- **필터 툴바**(탭 하단 가로 줄):
  - 좌측 토글 칩: `전체` / `내가 작성한` (세그먼트 토글, 회사 문서함엔 없음)
  - 구분 막대 `|`
  - 드롭다운 칩들: `👤 작성자 ▾` · `📋 양식 ▾` · `📑 업데이트일 ▾` · `+ 필터 추가`(굵은 버튼)
  - 우측 끝: `0건` 카운트 · `초기화`(텍스트 버튼) · `보기 저장`(초록 외곽선 버튼)
- **우측 상단 보조 컨트롤**(탭 줄 우측): `🔍`(검색) · `↓F 정렬` · `▦ 그룹` · `⚙ 보기 ▾`
- 색상: Flex 시그니처 초록(#1ec800 계열) CTA + 초록→청록 그라데이션. 슬레이트 그레이 텍스트, 흰 배경 카드.

## [175109] 내 문서함 — 진행중 탭 (필터 적용 후 빈 상태)

1. **화면 식별** — 워크플로우 > 내 문서함 > 진행중. URL `flex.team/workflow/archive/my/?tab=in-progress`. 브라우저 탭 제목 "내 문서함".
2. **레이아웃** — 위 공통 레이아웃. 본문 중앙에 회색 동그라미 빈상태 아이콘(`!` 형태).
3. **verbatim**
   - 타이틀: `"내 문서함"` `"회사 문서함"`
   - 탭: `"진행중"` `"완료"` `"중요"` `"전체"`
   - 우측 버튼: `"문서 양식 관리"` `"문서 작성하기"`
   - 필터 칩: `"전체"` `"내가 작성한"` `"작성자"` `"양식"` `"업데이트일"` `"+ 필터 추가"`
   - 우측: `"0건"` `"초기화"` `"보기 저장"`
   - 빈상태 제목: `"필터 검색 결과가 없어요."`
   - 빈상태 보조: `"필터를 다시 설정해보세요."`
   - 빈상태 버튼: `"필터 초기화"`
4. **선택창** — 없음(닫힌 상태).
5. **이벤트** — `필터 초기화` 클릭 시 적용된 필터 제거 → 전체 진행중 문서로 복귀(추정). `보기 저장`은 현재 필터+정렬+그룹 조합을 저장된 뷰로 등록(추정).
6. **왜(rationale)** — 전자결재(워크플로우)에서 "내 문서함/진행중"은 **본인이 기안했거나 본인이 결재선에 포함된 진행 중 문서**를 모으는 개인 인박스. 결재 SaaS의 핵심 진입점. `필터 검색 결과 없음`과 `진행 중 문서 없음`을 **별도 빈상태**로 구분 — 전자는 필터 탓, 후자는 데이터 없음. UX적으로 "무엇을 해야 하는지"를 다르게 안내(필터 초기화 vs 작성하기).

## [175120] 내 문서함 — 작성자 필터 드롭다운 (구성원 선택)

1. **화면 식별** — 진행중 탭에서 `작성자 ▾` 칩 클릭 → 작성자(구성원) 선택 드롭다운 펼침.
2. **레이아웃** — 칩 아래로 떨어지는 드롭다운. 상단 초록 외곽선 검색 인풋, 그 아래 카운트, "선택없음" 우측 컬럼(2-pane: 좌=후보, 우=선택됨). 각 구성원은 색상 이니셜 아바타(수빈=라임, 연우=초록, 성현=보라, 락윤=청록, 성주=슬레이트, 세진=슬레이트, 수로=노랑, 유민=슬레이트, 한빈=슬레이트, 형주=슬레이트, 훈이=보라) + 이름 + 소속 회사명.
3. **verbatim**
   - 검색 placeholder: `"검색"`
   - 카운트: `"총 0명 선택"`
   - 섹션 헤더: `"나"` (상단), `"구성원 목록"`
   - 우측 패널: `"선택없음"`
   - 구성원 행(이름 + 소속): `"강수빈 (주)대모산개발단"` `"강연우 (주)대모산개발단"` `"고성현 (주)대모산개발단"` `"김락윤 (주)대모산개발단"` `"김성주 (주)대모산개발단"` `"김세진 (주)대모산개발단"` `"김수로 (주)대모산개발단"` `"김유민"`(소속 미표기=본인) `"김한빈 (주)대모산개발단"` `"김형주 (주)대모산개발단"` `"나훈이"`
4. **선택창 구성** — 검색 인풋 / `나`(본인 빠른선택) 항목 / `구성원 목록` 전체 / 우측 `선택없음` 영역(선택 시 칩 누적). 다중 선택 가능(카운트 "총 N명").
5. **이벤트** — 구성원 행 클릭 → 우측 선택 패널로 이동 + 카운트 증가. 검색어 입력 시 실시간 필터.
6. **왜** — 결재 문서를 **작성자(기안자) 기준**으로 좁혀보는 필터. 관리자/팀장이 특정인이 올린 문서를 추적할 때, 또는 본인(`나`)이 쓴 문서만 볼 때 사용. 소속 회사명을 병기하는 건 **멀티테넌시**(한 User가 여러 Company 소속 가능) 환경에서 동명이인·타사 인원 구분 목적. Teamlet의 `RecipientPicker`(docs anti-pattern #10, 재사용 4곳)와 동일 패턴.

## [175129] 내 문서함 — 양식 필터 드롭다운 (양식 카테고리별 목록)

1. **화면 식별** — `양식 ▾` 칩 클릭 → 양식(폼 템플릿) 선택 드롭다운.
2. **레이아웃** — 검색 인풋 + 카운트 + 카테고리별 그룹 헤더 + 각 양식은 작은 이모지/스티커 아이콘 + 이름.
3. **verbatim**
   - 검색 placeholder: `"양식 검색"`
   - 카운트: `"총 0개 선택"`
   - 카테고리 `"구매 신청"`: `"비품 신청"` `"계정 신청"`
   - 카테고리 `"복리 후생"`: `"경조비 신청"` `"식비 사용 내역"`
   - 카테고리 `"비용 처리"`: `"출장비 신청"` `"식비 사용 내역"` `"소프트웨어 구독비"`
   - 카테고리 `"계약"`: `"계약서 검토 요청"`
   - 카테고리 `"업무 신청"`: `"디자인 업무 신청"` `"신규 프로젝트"` (이하 스크롤)
4. **선택창 구성** — 카테고리(양식 분류) 단위 그룹핑된 양식 멀티선택. `식비 사용 내역`은 복리후생·비용처리 두 카테고리에 중복 등장(한 양식이 복수 분류 가능).
5. **이벤트** — 양식 클릭 → 선택, 해당 양식으로 작성된 문서만 필터.
6. **왜** — 전자결재 문서는 **양식(FormDocument 템플릿)** 단위로 종류가 갈림(비품신청·경조비·출장비 등). 한국 기업 결재의 대표 카테고리: 구매(비품/계정), 복리후생(경조사비·식대), 비용처리(출장비·SW구독료), 계약, 업무요청. 카테고리 = `ApprovalPolicy.category`로 결재선 정책을 묶는 단위. Teamlet의 `document_kind` + `ApprovalPolicy.category` 설계 근거와 직결.

## [175138] 내 문서함 — 업데이트일 필터 드롭다운 (기간 프리셋)

1. **화면 식별** — `업데이트일 ▾` 칩 클릭 → 날짜 기간 선택 드롭다운. URL `?tab=in-progress`.
2. **레이아웃** — 단순 텍스트 메뉴 리스트, 그룹 구분선으로 프리셋/커스텀 분리.
3. **verbatim** — `"오늘"` `"지난 1주일"` `"지난 1개월"` `"지난 3개월"` (구분선) `"월별 조회"` `"직접 입력"`
   - 이 화면의 빈상태(드롭다운 뒤): 제목 `"진행 중인 문서가 없어요."`, 보조 `"결재가 필요한 문서를 작성해 보세요."`, 버튼 `"작성하기"`(초록).
4. **선택창 구성** — 상대기간 프리셋 4종 + `월별 조회`(달력 월 단위) + `직접 입력`(시작~종료 직접 지정).
5. **이벤트** — 프리셋 클릭 시 즉시 필터, `직접 입력`/`월별 조회`는 하위 캘린더/입력 패널 추가 노출(추정).
6. **왜** — 결재 문서는 시간이 지나며 대량 누적되므로 **기간 필터**가 필수. "업데이트일"(=최종 결재/수정 시각) 기준은 진행 중 건의 **최근 활동 추적**에 유용. `직접 입력`은 감사/정산 시 특정 기간 조회용. 빈상태가 [175109]와 달리 "필터 결과 없음"이 아닌 "진행 중 문서 없음"으로 바뀐 점 — 필터 미적용 기본 상태임을 시사.

6. **왜** — 결재 문서의 검색 차원은 **누가(작성자/승인자/참조자) · 무엇을(양식) · 언제(작성일/업데이트일) · 어떤 상태(진행중/완료/반려)**. 자주 쓰는 3개만 기본 노출, 나머지는 온디맨드로 추가 → 툴바 과밀 방지 UX. `승인자`/`참조자` 필터는 "내가 결재해야 할 / 참조로 받은" 문서 추적에 핵심.

   - 조직장 단축: `"1차 조직장"` `"2차 조직장"` `"3차 조직장"` `"4차 조직장"` `"5차 조직장"`(각 색상 번호 배지)
   - 그룹 `"조직"`: `"(주)대모산개발단"` `"디자인팀"` `"개발팀"` `"교육팀"` `"프론트엔드"`
   - 그룹 `"구성원 목록"`: `"강수빈 (주)대모산개발단"` `"고성현 (주)대모산개발단"` `"김락윤 (주)대모산개발단"` `"김세진 (주)대모산개발단"` …
4. **선택창 구성** — 두 가지 모드 토글: 평면 `목록 보기`(기본 추정) ↔ `조직도 보기`. 조직도 모드는 조직 노드 + **동적 역할(N차 조직장)** + 조직 + 개별 구성원을 한 번에 선택 가능.
5. **이벤트** — 항목 선택 → 해당 결재 단계/참조에 추가. 검색 시 필터.
6. **왜** — 결재선 지정은 **고정 인물뿐 아니라 "직책/역할"(N차 조직장)로 동적 지정**해야 인사이동 시에도 결재선이 깨지지 않음. `1차 조직장`=직속 상위 조직의 장, `2차`=그 위… → 신청자 기준 상대적 결재선. Teamlet의 **동적 역할(조직장)** + Scope 설계(CLAUDE.md "동적 역할(조직장)")와 정확히 일치. `RecipientPicker` 재사용 지점.

## [175450] 양식 만들기 — 결재자/참조 피커 ("목록 보기" = 조직 트리)

1. **화면 식별** — [175438]에서 토글이 `목록 보기`로 전환된 상태(우상단 버튼 라벨 `목록 보기`). 조직 트리 확장형 표시.
2. **레이아웃** — 검색 + `목록 보기` 토글. 트리: `▾ (주)대모산개발단` 아래 `▸ 디자인팀` `▸ 개발팀` `▸ 교육팀` `▸ 이사`(접힌 하위 조직, 삼각형 토글) + 그 아래 개별 구성원 아바타 리스트.
3. **verbatim**
   - 토글 버튼: `"목록 보기"`
   - 트리: `"(주)대모산개발단"` > `"디자인팀"` `"개발팀"` `"교육팀"` `"이사"`
   - 구성원: `"강수빈"` `"고성현"` `"김락윤"` `"김세진"` `"김수로"` `"박민영"` `"이원길"` `"장태준"` `"전민주"` `"정세윤"` …
4. **선택창 구성** — 조직 트리 펼침/접힘 + 리프 구성원 선택. (조직도 보기 ↔ 목록 보기 상호 토글)
5. **왜** — 같은 데이터의 **두 표현**: (a) 조직도 보기 = 역할/조직 중심(동적 결재선), (b) 목록 보기 = 회사→팀→인원 계층 탐색. 큰 조직에서 부서 단위로 빠르게 드릴다운. 두 모드 제공 = 결재선 지정 UX 완성도.

## [175532] 양식 만들기 — 승인 단계 추가 후 (2단계 승인 생성)

1. **화면 식별** — `+ 승인 단계 추가하기` 클릭 후. 우패널에 `2 단계 승인` 섹션 추가됨.
2. **레이아웃** — 우패널 순서: `양식 분류` → `요청자별 승인`·`변경 허용` → `참조`(추가하기 / 참조자를 추가해 주세요.) → `1 단계 승인`(추가하기 / 승인자를 추가해 주세요.) → `2 단계 승인`(추가하기 / 승인자를 추가해 주세요.) → 하단 `+ 승인 단계 추가하기`(부분 노출).
3. **verbatim**
   - `"참조"` / `"추가하기"` / `"참조자를 추가해 주세요."`
   - `"1 단계 승인"` / `"추가하기"` / `"승인자를 추가해 주세요."`
   - `"2 단계 승인"` / `"추가하기"` / `"승인자를 추가해 주세요."`
4. **이벤트** — 단계 추가 시 `N 단계 승인` 섹션이 순차 누적. 각 단계마다 승인자 추가(피커). 단계 삭제/순서변경 가능(추정).
5. **왜** — 한국 기업 결재는 **다단계 순차 승인**(팀장→부서장→임원…)이 표준. 각 단계는 독립 승인자 그룹을 가지며, 이전 단계 승인 후 다음 단계로 진행(순차 워크플로우). `참조`는 결재권 없이 통보만 받는 대상. Teamlet `ApprovalPolicy`의 단계(step) 시퀀스 + 참조자(cc) 모델과 직결. anti-pattern #10(`RecipientPicker` 재사용 4곳) 적용 대상.

## 종합 인사이트 (Teamlet 구현 메모)

- **내 문서함(/my) vs 회사 문서함(/all)**: 같은 워크플로우 데이터의 개인 인박스 vs 권한범위 전사 뷰. 탭 구성 다름(개인=진행중/완료/중요/전체, 회사=중요 제외). `내가 작성한` 토글은 개인 문서함 전용.
- **상태 모델**: 진행중 / 완료(=승인완료·반려·취소 종결) / 중요(개인 별표). 빈상태 문구가 필터 적용여부·탭별로 정교하게 분기 → Teamlet도 컨텍스트별 빈상태 분리 권장.
- **양식(FormDocument 템플릿) = 폼 필드/본문 + 결재선(참조 + N단계 순차 승인)**. 분류(category) N:M, 동적 역할(1~5차 조직장)로 결재선 지정, `요청자별 승인`(조건부 분기), `변경 허용`(기안자 결재선 수정), `템플릿`(결재선 재사용)이 4대 결재 정책 옵션.
- **컬러 주의**: 전 화면 Flex 초록/청록 그라데이션 CTA — CLAUDE.md 원칙 5(그라데이션 금지, Cool Slate)로 **반드시 변주**. 패턴(2-pane 피커, 조직도/목록 토글, 단계형 결재선 UI)만 차용.
