# HR 웹 프로젝트 컨텍스트

> 새 대화 시작 시 이 문서를 붙여넣어 컨텍스트 이어가기
> **최종 업데이트**: 2026.5.19 — Flex 전체 분석 완료, 명세서 작성 단계 진입

## 🎯 핵심 원칙 (절대 잊지 말 것)

1. **UX/UI 사용자 중심** — 기능보다 사용 경험이 우선
2. **Flex 카피 금지** — 패턴은 차용하되 **적절한 변주** 필수
3. **목표: Flex 대체** (간소화 ❌) — 풀스펙·고완성도, SaaS 대체 수준
4. **범용성** — 대부분 한국 기업이 쓸 수 있어야 함
5. **컬러 차별화** — Flex의 초록→청록 그라데이션 사용 금지, 다른 웹처럼 보여야 함

## 프로젝트 개요

- **목표**: 대부분의 기업에서 사용 가능한 **범용 HR SaaS** 구축 (Flex 대체 가능 수준)
- **방향성**: 풀스펙 지향, 단계적(Phase) 개발
- **연계**: AxHub 생태계 안의 한 앱. AxHub API는 아직 개발 전이라 당분간 **수기 입력** 기반, 나중에 API 연동 전환
- **인증 구조 (확정)**: **독립 회원가입 + AxHub 연동은 옵션** (자체 인증 유지)
- **회사 생성 (확정)**: 승인 가입 — 관리자 또는 세일즈 프로세스 (B2B SaaS 표준)
- **직원 가입 (확정)**: 회사코드 + 관리자 승인 (Flex 스타일)
- **현재 단계**: 분석 완료, 명세서 작성 단계 진입

## 스코프 결정 (최종)

### ✅ 핵심 스코프 (MVP / P0)

1. **구성원 (Core HR)** — 시점 기반 인사 이력 필수
2. **휴가 관리** — 정책 엔진 + 회계장부형 이력
3. **채용** — 공고 + 후보자 (사이트 빌더 제외)
4. **홈 / 대시보드** — 피드 + 할 일 + 캘린더
5. **워크플로우 (휴가 결재용 우선)** — 1단계 결재부터
6. **설정 / 권한** — 회사정보/쉬는날/인사체계/연차정책/권한
7. **회사 문서 보관소** — 파일 업로드/다운로드만 (단순)
8. **알림** — 인앱 단일 채널, 회사별 보존 정책 (30/90/180/무기한)
9. **전역 검색 (⌘K)** — 커맨드 팔레트 + AI 자연어 명령 ⭐ 차별화
10. **동료에게 전달하기** — 공지/할일요청/작성요청 (P0)
11. **회사 가입/등록 흐름** — User/Company/Membership 다대다, 회사코드

### ⚠️ 후순위 (Phase 2+, P1~P2)

- **증명서 발급** (재직/경력) — 인사 이력 완성 후 PDF만 추가
- **인정/피드백 메시지** — P1로 확정 (피드백은 sender↔recipient 1:1 비공개, HR도 못 봄)
- **채용 사이트 빌더**
- **후보자 평가 양식**
- **입퇴사 체크리스트** — 신규 발견, 온/오프보딩 자동화
- **구성원 인사노트** — 직원별 메모 (HR 평가 노트, 채팅 타임라인 형식)
- **자동 발송** — 입퇴사 이벤트 트리거 자동 워크플로우
- **권한 위임 (PermissionDelegation)** — 휴가 중 권한 위임
- **외부 연동** — Slack / Google Calendar (P2, AxHub 연동 후)
- **교육 이력 관리** — 법정 의무 교육 추적 (P1)
- **성장 일지** — 본인 작성, Phase 4 평가 영역 (P2 보류)

### ❌ 제외

- **근태 관리** — 차별화 어려움 (현직자 조언)
  - Flex의 "근무" 그룹 전체 (근무 유형 / 근무 정책·승인 / 초과 근무 보상 / 근무지)
  - 실시간 근무 기록 / 자동 근무 기록
  - **단, 휴가 모듈은 "1일=8시간, 주 40시간 고정 근무" 가정으로 단순화**
- **급여** — 법적 복잡도 과대 (4대보험/세금)
- **평가 / OKR** — Phase 4 영역
- **인사이트 통계** — 데이터 부족
- **계열사 관리** — 단일 회사 가정
- **커스텀 승인 라벨** — 오버스펙 (승인/반려 enum만)
- **단체 보험** — 부가 모듈

## 핵심 설계 결정 사항

### 1. 시점 기반 인사 이력 (가장 중요)
- 직원 정보를 단순 UPDATE로 덮어쓰면 안 됨
- **별도 이력 테이블에 발령일 기반으로 쌓기**
- "X월 X일 시점에 누가 무슨 직책이었나" 조회 가능해야 함
- **각 도메인별 별도 이력 테이블**: 인사 정보 / 근로 계약 / 임금 계약 / 급여 지급 / 근무 / 초과 근무 보상 (Flex 패턴)
- 구성원 상세 페이지 우측 상단 "정보 변경 내역" 버튼 — 도메인별 탭으로 이력 조회

### 2. 휴가 정책을 데이터로 (정밀)
- 휴가 종류별 부여 정책을 코드에 박지 말고 DB에
- **연차와 맞춤 휴가는 별도 엔진**:
  - 연차: 회계일/입사일 모드 + 월차/연차 이중 회계 + 비례 부여 + 소수점 처리
  - 맞춤 휴가: 6가지 부여 방식 (신청시/연차소진시/관리자직접/입사시/반복/근속시)
- 새 휴가 추가가 코드 수정 없이 가능하게

### 3. 워크플로우 엔진 통합
- 휴가/일반결재/구성원정보변경 모두 같은 결재 인프라
- `ApprovalPolicy` 테이블에 `category` 컬럼으로 구분
- **연차 정책, 맞춤 휴가, 모든 정보 변경 모달이 동일한 "승인·참조자 선택" 컴포넌트 재사용** (Flex 검증)
- "요청자별 승인" / "변경 허용" 옵션 칩 표준 지원

### 4. 양식 정의를 동적으로
- 휴가만 만들어도 데이터 모델은 동적 폼 구조
- `form_templates` + `form_documents (answers JSON)` 패턴
- 동료에게 전달하기 3종 (공지/할일/작성요청) = `FormDocument`의 `document_kind` 분기로 통합

### 5. 권한 모델 — RBAC + Scope + 동적 역할
- 권한 그룹 = N개 (시스템 1 "최고관리자" + 동적 1 "조직장" + 기본 1 "기본권한" + 사용자정의 N)
- 권한 마스터 = 단일 카탈로그 (~70개)
- 권한 = "조회 / 관리" 페어 패턴 + 범위(scope) 옵션
- 범위(scope) = 전체 / 부서 / 직속 부하 / 본인
- **동적 역할 "조직장"** — `PositionHistory.is_organization_head = true`인 사람에게 자동 부여
- 양방향 뷰: 권한 그룹 ↔ 구성원 권한 (디버깅용)
- 감사 로그 처음부터 인프라로

### 6. 멀티 테넌시 (User ↔ Company 다대다)
- `User` = 인증 단위 (회사 무관)
- `Employee` = 특정 회사에서의 직원 신분 (회사 N개에 소속 가능)
- `UserCompanyMembership` = 다대다 + 멤버십 상태
- 회사코드(XXXX-XXXX) 발급 → 직원이 입력 → HR 승인 흐름

### 7. 한국 비즈니스 특화
- 법정 공휴일 시드 + 음력 변환 라이브러리
- 사업자등록번호 / 법인등록번호 분리
- 연차 정책: 입사 1년 미만 월 1일, 1~3년 15일, 3년+ 2년마다 +1일
- 노동절 = 필수 휴일 (삭제 불가)
- **법정 휴가 8종 시드 데이터** (가족돌봄/군소집훈련/난임/배우자출산/보건/보상/산전후-본인/산전후-미숙아)
- **국적/거주국가/체류자격/외국인등록번호** — 외국인 직원 지원
- **장애인·국가유공자 / 총 공제 대상** — 세제 혜택 처리
- **연차 사용 촉진제** (스마트 연차 촉진) 자동화
- **ISMS-P 인증 대응** — 비밀번호 복잡도/주기/실패잠금/세션만료/이력
- **특이사항 = 세제 플래그 4종** (육아단축/외국인세율/소득세감면/학자금) — 자유 텍스트 아님

### 8. UX 패턴 표준화 (Flex 검증 + 우리 변주)
- 모든 변경 모달에 ⚙(결재선) + "적용일 오늘" 칩
- Retroactive 경고 명시 (휴가/쉬는날 변경 시)
- 미저장 변경 가드 (Dirty State Guard)
- 점프 칩 (긴 폼 네비게이션)
- 양방향 뷰 (권한 그룹 ↔ 구성원 권한)
- "현재 접속 IP 추가" 같은 락아웃 방지 안전장치
- **`RecipientPicker` 표준 컴포넌트** (4곳에서 재사용: 결재선/참조선/정보변경/동료에게 전달)

Flex에 없거나 우리가 더 잘 할 것:

| # | 항목 | Flex | 우리 |
|---|---|---|---|
| 1 | **⌘K / Ctrl+K 단축키** | ❌ | ✅ P0 |
| 2 | **AI 자연어 명령** ("내일 휴가 신청") | ❌ | ✅ P0 |
| 3 | **한국어 형태소 검색** (pg_trgm + Mecab) | 불명 | ✅ P0 |
| 4 | **AxHub 통합 IdP** (셋업 빠름) | N/A | ✅ |
| 5 | **피드백 = 완전 1:1 비공개** (HR도 못 봄) | 불명 | ✅ 명시 |
| 6 | **인정/피드백 회사별 커스터마이즈** | 시스템 고정 | ✅ 회사별 |
| 7 | **컬러 차별화** — Flex 그라데이션 안 씀 | 초록→청록 | 별도 정의 (디자인 시스템에서) |
| 8 | **AxHub Adapter** — 수기→API 무중단 전환 | N/A | ✅ 설계 단계부터 |

## Phase 로드맵

```
Phase 1 (Foundation)
└── User, Company, Membership, 회사가입/직원초대, 권한 카탈로그, 로그인

Phase 2 (Core HR)
└── 직원 정보, 조직도, PositionHistory, Appointment, 발령

Phase 3 (휴가)
└── CompanyHoliday, LeavePolicy, LeaveType, LeaveTransaction, LeaveRequest

Phase 4 (Workflow + 검색)
└── FormTemplate, FormDocument, ApprovalPolicy, 전역 검색(⌘K), AI 명령

Phase 5 (채용)
└── JobPosting, JobStage, Candidate

Phase 6 (문서/보안)
└── CompanyDocument, CompanySecurityPolicy (2FA + IP), AuditLog 강화

Phase 7 (P1)
└── 인정/피드백, 인사노트, 휴직이력, 가족/경력/학력, 입퇴사 체크리스트

Phase 8 (확장)
└── 자동 발송, 외부 연동 (Slack, Google Calendar), 증명서 발급
```
